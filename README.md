# 唤生 SpiritAgent

### 让想象中的伙伴，来到你的桌面。

**会陪伴、能做事的专属 AI 伙伴。**

## 我们想创造怎样的伙伴？

我们希望，人与 AI 的交互不只发生在“提出问题—得到回答”的片刻。

在一次次请求之外，也可以有一个熟悉的形象、一段能够延续的相处，以及一些共同完成的事情。唤生围绕“同一个伙伴”组织这些体验：形象让它拥有可辨认的存在，记忆让互动留下积累，行动能力让它不只停留在交谈中，也能参与日常。

我们想探索的，不是给工具加上一层可爱的外壳，而是让陪伴与能力成为同一段体验的不同部分。

### 相遇，由你参与

初次见面，是一颗等待被唤醒的蛋。你描述它的样貌，为它取名，设定性格与说话方式，再逐步确认它的形象与音色。

这不只是一次初始化。我们希望，你参与的是一个伙伴的诞生，而不是从已有的角色列表中领取一个默认答案。

### 让相处留下痕迹

初次定义决定“它是谁”，持续互动则让相处逐渐有了内容。长期记忆让伙伴在后续交流中参考你的偏好与过往信息；片刻与日记，则让一些值得留下的经历有了可以回看的形态。

我们希望，时间带来的不只是更多聊天记录，还有更少的重复介绍，以及逐渐积累的熟悉感。

### 陪你聊天，也和你一起做事

你可以在生活空间分享日常，也可以进入工作台，请伙伴查阅资料、处理文件或协助编程。两个入口承载不同的交流方式，共享同一个伙伴的身份、形象与长期记忆，同时让生活与工作的聊天历史彼此独立、互不干扰。

轻松聊天时是它，认真做事时也是它。变化的是相处方式，而不是你面对的伙伴。

### 靠近，也保留空间

我们不把更频繁地说话，等同于更好的陪伴。你可以调整伙伴的主动程度：让它自由表达、安静地待在原处，或停止实时主动行为。

唤生追求的，不是尽可能多地占据你的注意力，而是一种你愿意长期保留的相处方式。

## 伙伴能做什么

| 场景 | 体验 |
|---|---|
| 定义你的伙伴 | 用文字或参考图描述外貌、性格与说话风格，确认形象与音色，生成可动的 2D 或 3D 形象；2D 衣柜支持描述新装并微调 |
| 桌面相伴 | 呼吸、眨眼、视线跟随、拖拽与触摸反馈，让伙伴在桌面保持存在感；自主档可漫游、贴边栖息或主动搭话 |
| 日常聊天 | 生活空间提供含伙伴的房间画面、文字与语音对话、片刻时间线和第一人称日记 |
| 一起工作 | 工作台集中展示会话、工具过程与运行轨迹，伴工形象随窗口一起移动 |
| 交付任务 | 借助本机终端、文件、浏览器、代码执行与屏幕感知完成任务，可通过 Skills 扩展能力 |
| 延续相处 | 长期记忆为后续交流提供过往信息；夜间可整理互动、写日记，并在已开启的能力范围内规划自主活动 |
| 控制打扰 | 自主、常规、静止三档配合全屏等活动场景，控制在线时的实时主动陪伴程度 |
| 跨端联系 | 通过微信 iLink 与同一伙伴对话；涉及本机操作时，电脑上的客户端与 Runner 须在线 |

双击桌面伙伴会打开上次使用的生活空间或工作台。两种入口共享伙伴身份与长期记忆，但分别保留适合生活和工作的对话上下文；语音、外观与主动行为可在设置中调整。

## 当前状态与边界

唤生仍是一个需要自行部署和配置的项目。桌面端支持 Windows 与 macOS，后端运行在 Linux Docker 容器中；完整体验需要后端服务、模型供应商，以及本机客户端和 Runner。模型、图像与语音能力会使用所配置供应商的服务并消耗相应额度，因此它不是完全离线应用。

- **记忆不是对角色定义的自动改写**：角色的核心设定由用户明确给出并由用户发起修改；互动记忆用于影响后续交流和运行时表现，不会让系统自行重写“它是谁”或不断重生成形象。
- **静止不等于停止所有后台活动**：三档打扰设置控制用户在线时的实时主动消息、表达与移动；普通自动化和夜间记忆整理、自主活动由各自的设置与开关独立控制。
- **本机执行与云端状态彼此分工**：角色定义、会话、记忆与形象资产由后端管理；终端、文件和浏览器等本机操作由 Runner 在当前用户权限下执行，并由客户端中转。后端不直接访问本机文件系统，Runner 也不持有后端凭据。
- **工具能力会产生真实影响**：读取文件、运行命令和操作浏览器不是演示效果。请只连接可信的后端与跨端账号，并根据任务谨慎开放本机能力。
- **形象生成允许失败，但桌面不会空白**：3D 不可用时会回退到已就绪的 2D 形象；动态形象均不可用时，程序化蛋形继续承担最终兜底。

## 如何运行

已有安装包时，运行唤生安装器完成本机环境安装，再在客户端填写服务地址与激活码。自行构建安装包见 [构建说明](scripts/README.md)。

### 从源码启动

准备 Docker Compose、Node.js 与 pnpm；Node.js / pnpm 版本要求见 [client/package.json](client/package.json)。本机工具需要安装器建立的 Runner 环境，仅启动前端不等于完成本机环境安装。

1. 在 `backend/` 下复制 `config.toml.example` 为 `config.toml`，按模板设置数据库、签名密钥和初始管理员凭据。
2. 在该目录启动后端与数据库：

   ```bash
   docker compose up -d --build
   ```

3. 打开 [本地管理端](http://localhost:10620/admin/)，用配置的管理员账号登录。在“系统设置”配置供应商与所需能力，再创建用户并获取激活码。供应商 API Key 在管理端配置，具体部署与调试见 [后端说明](backend/README.md#7-部署与监控)。
4. 在仓库根运行：

   ```bash
   pnpm --dir client install
   pnpm --dir client dev
   ```

5. 在客户端填写服务地址与激活码，唤醒蛋并开始定制伙伴。
