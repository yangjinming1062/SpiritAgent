# 架构设计

本文定义模块职责、状态归属、信任边界与项目级技术取舍。产品体验归 [DESIGN.md](DESIGN.md)，跨模块交付语义归 [PROTOCOL.md](PROTOCOL.md)，形象生成与产物归 [PIPELINE.md](PIPELINE.md)；文档维护规则见 [RULES.md](../RULES.md)。

按任务阅读：模块与状态边界读 §1–§3，通信读 §4，调度与部署读 §5，角色与记忆读 §6，安全边界读 §7；变更联动与模块入口见 §8–§9。

## 平台支持策略

- Backend 通过 Docker 部署，以 Linux 容器为运行环境，不维护 Windows / macOS 原生兼容性。
- Client、Runner 与 Installer 仅支持 Windows 和 macOS 原生运行。进程控制、路径与 IPC 必须遵守对应平台约束，具体封装见各模块 README。

## 1. 三模块物理解耦

| 模块 | 职责 | 边界与理由 |
|---|---|---|
| Backend | 对话与模型编排、云端工具、角色和记忆、形象与房间生成、调度及持久化 | 统一管理跨设备状态、供应商调用和用户隔离；本机操作必须经 Client 委托 Runner |
| Client | 桌面形象与窗口、身份凭据、本地设置、云端连接、Runner 生命周期与请求中转 | 主进程连接云端和本机执行环境；渲染层处理交互与呈现，不直接持有后端登录凭据 |
| Runner | 终端、文件、浏览器、代码执行等本机工具，报告实际可用能力 | 在用户本机执行，不持有后端登录凭据或模型供应商密钥；所需模型能力经 Client 代理 |

进程拆分用于隔离职责和凭据，不等于本机工具处于完整安全沙箱。Runner 可以访问获准的本机资源，工具结果也可以经 Client 返回云端；具体信任边界见 §7。

## 2. 架构拓扑

交互主链为 Backend web 进程 ↔ Client 主进程 ↔ Runner。Backend 连接 PostgreSQL、资产存储与模型供应商；Client 将事件交给渲染层，将本机工具调用交给 Runner。

Installer 负责首次安装：准备本地 Python 运行时、Runner wheel、客户端与基础 Skills。安装完成后的进程管理和更新由客户端接管；安装操作见 [installer README](../installer/README.md)，首次使用体验见 [DESIGN §5](DESIGN.md#5-初始化与-onboarding)。

## 3. 状态归属

| 状态 | 权威位置 | 其他参与方的职责 |
|---|---|---|
| 角色定义、会话、长期记忆、片刻与日记 | Backend 按用户及相应预设持久化 | Client 展示和提交用户操作；Runner 不维护副本 |
| 形象、外观与房间资产 | Backend 保存资产及激活关系 | Client 下载、缓存和渲染；缓存不自行改变激活状态 |
| 非机密用户设置 | Backend 为真源，Client 持镜像 | 按 [PROTOCOL §2.4](PROTOCOL.md#24-配置所有权与云端同步) 同步；设备派生状态不能覆盖用户偏好 |
| 本机连接配置、机密设置、登录凭据 | Client 主进程按平台机制保存 | 只向 Runner 下发执行所需的本机配置，不下发后端登录凭据 |
| 窗口开关、上次入口、桌面位置、当前渲染状态 | Client | Backend 不决定开窗和像素坐标；仅接收契约明确需要的可用性与环境信号 |
| 本机工具能力与执行状态 | Runner 报告实际能力；Client 维护连接与能力镜像 | Backend 按同步结果决定是否开放本机工具；注册信息不代表执行一定成功 |
| 主动陪伴意图、定时任务和待投递事件 | Backend 数据库 | 在线连接、正在输入等短期信号留在运行时，不能当作持久事实 |

同一状态的镜像、缓存与派生值必须能追溯权威来源。断连与恢复不能靠客户端当前视图覆盖数据库中已提交的结果。

## 4. 通信形态与权衡

WebSocket 与本地 IPC 使用 JSON-RPC 2.0 组织双向请求和事件；HTTP REST 承载独立资源操作、上传和下载。资产事件传递标识与可访问地址，大文件经 HTTP 传输；用户图片附件可按协议以内联数据提交。信封、鉴权和通道选择见 [PROTOCOL §0–§1.1](PROTOCOL.md#0-契约总览)。

### 4.1 协议链路映射

Backend ↔ Client 使用鉴权后的 WebSocket 承载对话、控制、状态和工具事件；连接前以登录凭据换取短时 ticket。REST 请求独立鉴权，资源操作不以聊天在线为前提。

Client ↔ Runner 使用 Windows 命名管道或 macOS UDS 承载 WebSocket 帧。Client 是本地 RPC Server，Runner 主动连入；每次启动生成握手 token，macOS 另以 socket 文件权限限制访问。选择这条链路的原因是：

1. 工具库的标准输出和底层日志不会污染协议帧。
2. 请求可以全双工并发，按调用标识匹配响应。
3. 本地端点不监听 TCP 端口；端点发现、重连与准入仍须遵守 [PROTOCOL §2](PROTOCOL.md#2-client--runner-契约)。

### 4.2 核心数据流（架构级）

- **本机工具调用**：Backend 根据已同步能力与调用上下文派发 → Client 中转 → Runner 校验并执行 → Client 回传 → Backend 续接回合。离线、取消、超时和结果不明各有独立收尾语义，不能把重发等同于恢复；见 [PROTOCOL §2.5](PROTOCOL.md#25-本机调用日志)。
- **反向模型请求**：Runner 工具 → Client 以自己的后端身份代理 → Backend 调用模型。Runner 不获得代理使用的登录凭据，见 [PROTOCOL §3](PROTOCOL.md#3-反向-rpc-桥接runner-借大脑)。
- **伙伴表达**：聊天、语音演绎、当前心情、视觉表达和空间决策分别交付。正文不携带控制信息，渲染与位置由 Client 决定，职责见 §6.3。

工具执行在生活空间与工作台的呈现不同，按 [DESIGN §6.1](DESIGN.md#61-双入口窗口架构与交互范式) 实现，不从底层帧格式推导产品界面。

## 5. 主动陪伴与事件机制（Cron + Outbox）

主动陪伴采用事件或时间唤醒的有界 Agent Loop：数据库保存待兑现意图和等待条件，满足条件时才调用模型，单次回合受轮数与时长预算约束。等待期间不保持 LLM 持续推理。

PostgreSQL outbox 将业务状态与待投递事件衔接起来：业务事务写入事件，数据库通知唤醒消费循环，消费者原子认领并交付。需要共同生效的状态与事件在同一事务提交；通知只是唤醒信号，持久化行才是恢复依据。认领机制不等于端到端恰好执行一次，部署限制见 §5.3。

Cron 按产物语义分两轨，共享调度与数据库 CAS 抢占：

| 轨道 | 执行上下文 | 交付与在线要求 |
|---|---|---|
| `special` | 主陪伴会话，待兑现意图仅作为本轮运行资料 | 依赖新鲜桌面可用性信号；可以发言、沉默或保存下一次等待，正文交付主陪伴对话 |
| `standard` | 独立自动化任务会话，不装配伙伴人格或长期记忆 | 云端回合可离线运行；完整结果留在任务会话，桌面接收系统通知；本机工具仍要求桌面在线 |

`special` 的调度游标与意图原子提交；触发后自动删除一次性任务不撤销已交接意图，用户主动删除或修改源任务则同步撤销旧意图。同来源未完成触发合并，过时意图不追补。意图认领与内部执行事件原子提交；终态正文、下一次等待及消息事件也共同提交。沉默不写聊天消息，但可保留有目的的等待。

用户发言优先中断旧主动回合，后续对话可修改或取消意图。已经执行但结果不明的操作必须保留核对信息，不能自动重放并冒充成功。租约、有效期与恢复细节见 [PROTOCOL §1.8.1](PROTOCOL.md#181-cron-双轨契约)，内部实现见 [backend README](../backend/README.md)。

### 5.1 打扰档位约束

Client 根据用户偏好和本机活动计算生效档位，是生效值的计算权威。Backend 持久化用户偏好和生效值，供跨端恢复与主动入口闸门使用；水合只恢复偏好，不能把旧设备派生值当作新设备的当前状态，也不由 Backend 重新推导焦点情境。同步契约见 [PROTOCOL §2.4](PROTOCOL.md#24-配置所有权与云端同步)。

静止档在主动推理入口阻断调用，Client 同时停止相应请求。用户发起的聊天、直接互动及其心情维护不属于主动行为。档位也不代表用户在线：启动主动回合还须检查可用性、输入和锁屏信号。

夜间整理与在线打扰档位独立。夜间总控与各能力政策决定可用活动；模型在可用能力内选择行动或空计划，服务层负责再次核对政策、执行顺序、结果账本及失败隔离。只有成功事实进入后续叙事，计划不能变成已完成经历。具体体验和能力限制归 [DESIGN §6.2](DESIGN.md#62-主动陪伴与打扰档位)。

### 5.2 情境化视觉表达

Client 掌握真实空闲时间、屏幕锁定和精灵可见性，负责决定是否请求；Backend 掌握角色定义、记忆和形象能力，负责语义判断。只有满足自主条件时才咨询，打开完整入口并收起桌面精灵后停止。视觉表达与空间决策各自独立，不从聊天正文推导；产品条件见 [DESIGN §6.4](DESIGN.md#64-自主行为让形象活着)。

### 5.3 副本语义

当前 Backend web 按单副本部署——这是产品技术选择（当前没有扩容需求），不是待解决的缺陷。WebSocket、运行时会话、IPC 等待表、用户级锁和 IM 通道管理均有进程内状态；交互与主动陪伴必须在能访问对应连接和运行时的进程执行。

Cron CAS 和 outbox 原子认领支持竞争消费，部分状态已持久化或带持连路由，但这些机制不足以证明整个 web 服务可水平扩展。增加 web 副本前，须统一解决连接路由、回合互斥、关联状态和通道所有权；不能仅增加容器数或 worker 数。

### 5.4 IM 通道桥

当前注册微信 iLink 适配器，通道桥在 web 进程内运行。每个渠道绑定一条独立 IM 会话；入站消息直接启动云端回合，格式化后的答复从原渠道发出，桌面只读查看其历史。

IM 陪聊不要求桌面在线。本机工具则要求该用户 WebSocket 在线且 Runner 已同步可用工具；这一可用性必须进入回合上下文，离线工具不加入注册表。无头回合的本机调用经 Client 执行，但不切换桌面可见工作状态。

IM 与桌面陪伴共享同一陪伴预设记忆，渠道历史互不混流，专业预设不读取这些经历。配对、审批、停止和媒体限制见 [PROTOCOL §1.7](PROTOCOL.md#17-im-通道桥接apichannels)。

## 6. 角色定义与表达层契约

### 6.1 角色定义与预设装配

Backend 持久化角色定义，作为伙伴身份与性格的权威来源，只能由用户通过允许的编辑入口修改。运行时行为同时受角色定义、记忆、当前情境与任务约束影响，学习记忆不能自行改写身份。

系统预设由后端目录定义，对话编排按预设选择提示词与上下文。陪伴预设装配角色、穿着、情感和陪伴记忆；专业预设使用各自目标与本域资料；自动化使用独立任务边界。预设标识承担稳定的目标归属，不能只为改变措辞而改变记忆域。会话身份与设置归属见 [PROTOCOL §1.8](PROTOCOL.md#18-系统预设对话5-套并列的特殊会话)。

### 6.2 形象与环境资产（跨模块契约）

头像、全身种子图、2D 外观、3D 模型和房间图由 Backend 按用户保存，Client 消费签名资源并缓存。生成链与资产完整性见 [PIPELINE](PIPELINE.md)，资源访问见 [PROTOCOL §1.5](PROTOCOL.md#15-资产-url-签名与传输缓存)。

确认后的身份锁定，允许的种子图重绘、换装和首次 3D 升级均须保留该身份。记忆学习不触发模型重生，外观失败不能抹掉已有可用资产；允许的用户操作和降级顺序统一见 [DESIGN §1、§5.4](DESIGN.md#54-形象确认头像与全身立绘)。

房间中的角色按当前身份与穿着生成，房间图与动态模型解耦；换装联动、锁定与历史激活保护见 [PROTOCOL §1.2](PROTOCOL.md#12-伙伴生命周期方法方法级契约)。Backend 不为工作台生成工位背景，Client 负责两个入口的互斥呈现。

### 6.3 表达层契约

| 表达通道 | Backend 职责 | Client 职责 |
|---|---|---|
| 聊天正文 | 交付可阅读、可朗读的台词；陪伴正文不携带控制标签或动作旁白 | 按陪伴或工作场景显示答复、媒体与执行过程 |
| 语音演绎与合成 | 生成独立演绎信息，提供合成与媒体资源 | 按响应模式请求、排队与播放；播放不决定当前心情或空间行为 |
| 当前心情 | 陪伴回合或直接互动后更新独立角色状态 | 展示在身份区，不写成聊天气泡 |
| 视觉表达 | 根据可用形象能力产生结构化情绪与动作 | 将语义映射为可兑现的动画，处理加载与能力降级 |
| 空间决策 | 判断漫游、陪工、靠近或保持静止 | 解析本机目标、坐标和移动方式，遵守屏幕与用户交互约束 |

这些通道不能借用聊天正文传递控制，也不能把音频或资产尚未就绪误判为语义失败。事件、语音请求和消息交付定义归 [PROTOCOL §1.4](PROTOCOL.md#14-聊天心情视觉表达与空间契约)，用户可见节奏归 [DESIGN §6.6](DESIGN.md#66-对话节奏与状态分离)。

### 6.4 行为驱动的双层模型与记忆分层

角色定义提供稳定身份，记忆提供有证据的个性化上下文。新的记忆影响言语、心情与主动判断，不改变形象资产；身份锁定和外观变化遵循 §6.2。

长期检索记忆与生活叙事分开维护：前者用于有依据的事实召回，后者以片刻和日记供用户查看。叙事与助手表达不能反向成为用户偏好的独立证据；用户编辑过的日记只允许后台追加，不得覆写。

学习记忆以原始用户证据支撑原子判断，服务层负责来源、作用域、生命周期可见性和原子提交。候选、失效、过期及已遗忘内容不得重新进入聊天、状态和主动规划。证据维护与存储约束见 [记忆模块](../backend/services/domains/memory/README.md)，管理体验见 [DESIGN §8–§9](DESIGN.md#8-多预设并列的系统对话)。

### 6.5 记忆隔离边界

长期记忆及能重新进入模型上下文的派生事实统一归属 `(user_id, system_preset_id)`。同预设会话共享；不同预设的检索、长期背景、摘要历史、后台反思和学习技能互不读取，不存在全局共享池或空结果跨域回退。

会话创建时持久化有效预设，每轮从认证用户和会话解析固定作用域并核对实际提示词；缺失或未知预设必须阻止记忆访问。异步工具、委派、反思与回填继承调用域，核验父会话归属，不能读取界面当前选择或接受模型指定的归属和来源。已有历史的会话不能直接改目标。

自动化使用内部 `automation` 目标，不装配长期记忆、学习技能或记忆工具。时区、语言、连接配置与渲染资产可按用户共享；陪伴人格、情绪、关系和日记只装配给 `companion`。夜间调用前拆分输入，专业预设只维护本域记忆，不执行陪伴反思、日记和主动规划。

隔离沿用 PostgreSQL 与 pgvector，不拆物理数据库。备份是独立的人工管理入口；模型可读的定时任务元数据保留创建预设，陪伴主动任务只能由陪伴预设创建。协议与存储细节见 [PROTOCOL](PROTOCOL.md#预设记忆与学习作用域) 和 [记忆模块](../backend/services/domains/memory/README.md)。

## 7. 安全与准入控制（架构原则）

凭据与执行边界须由代码和运行环境落实，不能依赖角色设定或提示词承诺：

- Backend 保存模型供应商凭据，认证、资源访问与工具归属按用户校验。本机操作通过 Client 委托 Runner；Backend 不执行 LLM 生成的代码或为其启动执行容器。生成资产的质量与交付校验归 [PIPELINE](PIPELINE.md)。
- Client 主进程持有后端登录凭据，渲染层只使用受控桥接接口。Runner 不获得这些凭据或模型供应商密钥，但会持有本地 IPC 握手 token、工具所需连接配置及会话；“不持有后端凭据”不能扩大成“没有任何凭据”。
- Runner 的能力受操作系统账户、工具实现和配置共同约束。路径限制、危险命令拦截与网络访问检查降低风险，不将任意终端执行变成通用安全沙箱。文件、截图和工具输出可能进入云端上下文，不能承诺提示词注入只能影响本地且不会泄露数据。
- 用户隔离、保留参数覆盖、路径与网络准入、敏感信息脱敏均在相应边界校验。不可信内容的标记只帮助模型区分资料与指令，不能替代权限控制；具体约定见 [PROTOCOL §5](PROTOCOL.md#5-跨模块安全契约)。
- 更新包须经预取、验签与完整性校验后安装，失败不能绕过校验覆盖运行文件。私钥在仓库外或 CI Secret 保存，客户端只分发验签公钥；更新契约见 [PROTOCOL §5.5](PROTOCOL.md#55-自更新签名client--backend--installer--backend)，密钥操作见 [release-keys README](../scripts/release-keys/README.md)。

## 8. 全局开发不变量 (Invariants)

变更时按下表定位必须共同保持的约束；完整定义在所属章节维护。

| 变更 | 必须核对的边界 |
|---|---|
| 新增能力、移动服务职责 | §1–§3 的依赖和状态归属；§7 的凭据与执行边界 |
| 修改通信、恢复或工具执行 | [PROTOCOL](PROTOCOL.md) 的信封、身份、取消、结果去重与未知结果语义；不能跨生命周期复用标识 |
| 修改调度或增加副本 | §5 的有界唤醒、事务、在线闸门和单副本限制 |
| 修改角色、预设、记忆或提示词 | §6 的身份和记忆隔离；[RULES](../RULES.md#提示词设计与修改规范) 的提示词修改规则 |
| 修改形象、窗口或主动表现 | [DESIGN](DESIGN.md) 的呈现、打扰和故障规则；[PIPELINE](PIPELINE.md) 的产物兑现约束 |
| 修改安装、更新或本机运行 | 平台支持策略、各模块 README 与 [PROTOCOL §5.5](PROTOCOL.md#55-自更新签名client--backend--installer--backend) 的校验和安装边界 |
