# 架构设计

本文维护模块职责、依赖方向、状态归属和信任边界。

## 平台支持策略

Backend 运行于 Linux Docker 容器；Client、Runner 和 Installer 支持 Windows、macOS 原生运行。不将底层库的跨平台能力等同于产品已支持其他平台。

## 1. 三模块物理解耦

| 模块 | 负责 | 不负责 |
|---|---|---|
| Backend | 对话编排、供应商调用、云端工具、角色与记忆、资产、调度及持久化 | 本机工具执行、桌面窗口与像素坐标 |
| Client | 桌面交互与渲染、登录凭据、本地设置、云端连接、Runner 生命周期及请求中转 | 云端业务状态的权威副本 |
| Runner | 本机终端、文件、浏览器等工具，报告实际能力 | 后端登录凭据、云端角色与会话状态 |

进程拆分隔离职责和凭据，不构成完整安全沙箱。Installer 只负责首次安装和环境修复；安装后的运行与更新由 Client 管理。

## 2. 架构拓扑

```text
Client 渲染层 ←→ Client 主进程 ←→ Backend web ←→ PostgreSQL / 资产存储
                       ↕
                     Runner
```

Client 主进程是云端身份与本机执行的桥梁。Runner 请求模型能力时，经 Client 转交 Backend，不直接获取代理使用的凭据。

Backend 的依赖方向为 `adapters → application → domains`；业务层可使用 `infrastructure`，各层可使用 `contracts`。基础设施不反向导入业务层，跨域流程由应用层组织，注册和启停集中于 `bootstrap`。精确允许依赖及检查入口见 [Backend](../backend/README.md#3-架构设计)，不在本文复制包级清单。

## 3. 状态归属

| 状态 | 权威来源 | 副本边界 |
|---|---|---|
| 角色、角色卡、会话、长期记忆、片刻、日记 | Backend 数据库 | Client 展示和提交操作；不得用旧视图覆盖已提交数据 |
| 形象、外观、房间及激活关系 | Backend 数据库与资产存储 | Client 缓存字节和展示状态，缓存命中不改变激活关系 |
| 可同步用户偏好 | Backend 配置 | Client 保存带用户归属的离线镜像；冲突按协议处理 |
| 激活凭据、本机连接和机密配置 | Client 主进程 | 仅向 Runner 提供执行所需配置，不向渲染层暴露凭据 |
| 窗口、位置、当前可见表面 | Client | Backend 不决定开窗、桌面坐标和窗口吸附 |
| 本机能力及执行结果 | Runner | Client 同步能力；Backend 注册表不是执行成功的证明 |
| 定时任务、陪伴意图、待投递事件 | Backend 数据库 | 在线、输入、锁屏等短期信号不作为持久事实 |

角色卡绑定已确认的头像资产，管理固定外形；人设管理姓名、性格等设定，衣橱管理可变造型。角色卡领域层管理资料与并发编辑，生成应用层管理双图分析及初始资产衔接，流程见 [PIPELINE](PIPELINE.md#113-角色卡与固定外形)。

镜像、缓存和派生值必须可追溯权威来源。生效打扰档位由 Client 根据偏好与本机情境计算；Backend 使用上报值执行闸门，不自行推测桌面状态。

## 4. 通信形态与权衡

### 4.1 协议链路映射

Backend 与 Client 通过 WebSocket 交付持续会话和事件，通过 REST 操作独立资源。Client 与 Runner 使用本地 OS IPC 承载 WebSocket 帧，由 Client 建立端点、Runner 主动连接。
本地 IPC 避免标准输出污染协议，也不暴露 TCP 监听端口；它仍需要端点权限和启动 token。字段、鉴权与通道选择统一见 [PROTOCOL](PROTOCOL.md)。

### 4.2 核心数据流（架构级）

本机调用沿 `Backend → Client → Runner → Client → Backend` 返回。模型决定工具意图，各边界负责权限、能力、参数与状态校验。结果未知时进入核对流程，不把重发当成恢复。
聊天正文、语音演绎、心情、视觉表达和空间决策独立交付。Backend 产生语义，Client 负责可见表面、动画兑现与本机位置；正文不是控制通道。

## 5. 主动陪伴与事件机制（Cron + Outbox）

主动陪伴采用事件或时间唤醒的有界回合：数据库保存意图和等待条件，条件满足后才调用模型。等待期间不维持持续推理，单次回合有轮数、时长和有效期边界。
Cron 分为陪伴与普通自动化两轨，具体交付见 [PROTOCOL](PROTOCOL.md#181-cron-双轨契约)。用户发言优先于未提交的主动表达；沉默也是有效结果，不能制造占位聊天或循环催促。
需共同生效的业务状态与异步通知在同一事务写入 outbox。数据库通知只负责唤醒，持久化事件行负责恢复。聊天流沿会话 emitter 交付，不能把所有推送统称为 outbox；认领成功或发送成功也不等于端到端恰好执行一次。

### 5.1 打扰档位约束

在线主动行为同时检查生效档位和新鲜可用性信号。静止档在推理入口阻断主动调用，而不是生成后隐藏结果；用户主动聊天、直接互动和普通自动化不受此闸门限制。
夜间整理独立受总控与各能力政策约束。服务层在执行前重新检查许可，按真实结果记账；计划、失败或结果不明的行为不能成为已经发生的经历。

### 5.2 情境化视觉表达

Client 判断精灵是否可见、是否锁屏及是否满足空闲条件；Backend 结合角色、记忆和可用形象能力作语义判断。完整入口打开并收起桌面精灵后，停止桌面自主咨询。体验边界见 [DESIGN](DESIGN.md#64-自主行为让形象活着)。

### 5.3 副本语义

当前 Backend web 按单副本部署。WebSocket、运行时会话、工具等待表、用户锁及 IM 绑定均有进程内状态。
Cron 的数据库竞争认领和 outbox 持久化不代表整个 web 服务可水平扩展。增加副本或 worker 前，必须解决连接路由、回合互斥、调用关联、任务恢复和通道所有权；不能只修改容器数量。

### 5.4 IM 通道桥

IM 桥运行于 web 进程；每用户每渠道绑定独立历史，复用云端回合编排和陪伴记忆。云端陪聊不依赖桌面在线，本机工具依赖桌面连接与 Runner 工具同步。无头执行不切换桌面工作状态；审批与渠道限制见 [PROTOCOL](PROTOCOL.md#17-im-通道桥接apichannels)。

## 6. 角色定义与表达层契约

### 6.1 角色定义与预设装配

角色定义是稳定身份来源，只能经允许的用户入口修改。记忆影响表达和判断，不自行改写身份。陪伴、专业工作与自动化分别装配所需上下文，不能通过界面切换改变既有会话的归属。

### 6.2 形象与环境资产（跨模块契约）

资产生成、激活和渲染分离。换装与全身参考重绘不解锁身份；普通任务生图不改变当前房间。输入、派生失效与恢复归 [PIPELINE](PIPELINE.md)，显示降级归 [DESIGN](DESIGN.md#12-形象降级与兜底体系永不空白)。

### 6.3 表达层契约

正文用于阅读与朗读，语音元数据用于演绎，心情用于身份区，视觉表达用于动画，空间决策用于移动意图。任何一条通道的失败都不能伪造另一条通道的成功。

### 6.4 行为驱动的双层模型与记忆分层

检索记忆与生活叙事分离。长期判断须有原始用户证据；助手台词、片刻和日记不能反向成为用户偏好的独立依据。候选、失效、过期和已遗忘内容不能作为有效事实进入互动。

### 6.5 记忆隔离边界

长期记忆及可重新进入模型的派生事实统一归属 `(user_id, system_preset_id)`。同预设共享，不同预设不跨域召回或空结果回退。异步任务和委派继承服务端捕获的作用域，不读取界面当前选择。

`automation` 不装配长期记忆或学习技能；IM 使用陪伴域。时区、语言和渲染资产可按用户共享，陪伴人格、关系、情绪与日记只用于陪伴。存储和证据规则见 [记忆模块](../backend/services/domains/memory/README.md)。

## 7. 安全与准入控制（架构原则）

Backend 保管供应商凭据并校验用户与资源归属，不执行 LLM 生成的代码或为其启动执行容器；Client 主进程保管桌面登录凭据；Runner 仅持本地准入 token 和执行所需配置。渲染桥与工具入口各自校验能力，不能依赖提示词约束权限。
Runner 不是任意代码的安全沙箱。操作系统权限、路径和网络检查只能降低风险；文件、截图及工具结果可能进入云端上下文。不能承诺提示词注入只影响本机、绝不泄露数据。
更新、配置同步、保留参数、凭据存储和备份恢复的具体边界见 [PROTOCOL](PROTOCOL.md#5-跨模块安全契约)。

## 8. 全局开发不变量 (Invariants)

变更须同时核对职责与依赖、状态权威、凭据边界及失败恢复。不得用延迟导入掩盖循环依赖，用缓存冒充数据库状态，用重试掩盖未知副作用，或用文档承诺尚未实现的隔离与恢复能力。
跨端变化按 [PROTOCOL 维护规约](PROTOCOL.md#8-维护规约) 验证；文档与代码冲突时核实消费链，不通过修改文字掩盖实现缺陷。
