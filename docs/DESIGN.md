# 伙伴层交互设计

本文定义产品体验、设计理由与验收边界。协议与数据约束见 [PROTOCOL.md](PROTOCOL.md)，模块职责见 [ARCHITECTURE.md](ARCHITECTURE.md)，渲染实现见 [renderer README](../client/renderer/README.md)。

按改动定位：形象与动作读 §1–§3，首次使用读 §4–§5，窗口与日常交互读 §6，语音、预设和记忆读 §7–§9。生成链的姿态、供应商与产物细节归 [PIPELINE.md](PIPELINE.md)。

## 设计哲学

核心定位是提供持续陪伴与情绪价值，交互取舍遵循以下原则：

- 点击、等待和状态变化应让用户感到伙伴在回应；桌面形象通过呼吸、眨眼和微动作保持生命感，同时尊重打扰档位与降低动态偏好。
- 角色定义决定身份与性格，长期记忆影响当下言语、心情和主动行为。记忆不自行改写角色定义，也不触发身份重生。
- 伙伴表达由大模型结合情境产生；离线与机械降级的例外见 §6.3、§6.5 和 [RULES 原则七](../RULES.md)。系统通知不冒用伙伴口吻。
- 2D 与 3D 均为正式形象模式，首次使用默认 2D。资产等待或失败时始终保留可见陪伴，降级规则统一见 §1.2。

## 1. 形象资产与图像生成体系

### 1.1 图像生成场景与资产总览

所有伙伴形象围绕用户确认的身份保持一致；普通任务生图不改变伙伴外观或房间。

| 资产 / 场景 | 产品用途 | 身份与外观约束 |
|---|---|---|
| 半身头像 | 设置页、聊天头像及全身种子图的身份来源 | 根据角色描述与可选参考图获得，锁定规则见 §5.4 |
| 全身种子图 | 全身立绘、换装与 3D 种子的身份与身材参考；房间、自拍等出镜画面的优先参考 | 保留头像身份与全身比例，以优美自然的姿态展示，不直接作为动画形象的拆分输入 |
| 全身立绘 | 确认 2D 外观并生成动画形象 | 保留头像身份与全身种子图的身材比例；用户可在确认前微调，3D 立绘在升级时另行确认 |
| 服装外观 | 2D 衣橱换装 | 五官、物种与性别不变，服装、发型和配饰可换 |
| 房间背景 | 生活空间的全景与伙伴日常场景 | 角色以当前身份和穿着出现在房间内；不用作工作台背景 |
| 2D 动画形象 | 呼吸、转头、表情与身体动作 | 保留立绘画风，动作幅度受素材完整度和自然度限制 |
| 任务生图 | 用户请求的绘图、设计与创作 | 作为对话媒体交付；绘制伙伴本人时仍保持身份一致 |

每套服装具有伙伴生成的着装描述，使其能感知自己的穿着。衣着只调节表达方式，不能取代性格成为行为主导。

房间采用写实室内中远景，角色自然融入场景。构图与生成参考约束见 [PIPELINE](PIPELINE.md)，换装联动、房间锁定和历史回滚的体验见 §6.1。

### 1.2 渲染模式与降级体系（永不空白）

2D 模式保留立绘画风，通过面部、身体与发饰微动表达生命感；3D 模式提供立体形象与空间动作。首次引导不要求用户理解或选择技术路线，完成后可在形象设置中切换。

- 选择 2D 时优先显示就绪的 2D 形象；不可用时进入备用呈现，最终以蛋形守候。
- 选择 3D 时优先显示就绪的 3D 形象；加载失败或尚未就绪且 2D 可用时回退 2D，两者均不可用时显示蛋形。
- 头像确认前统一展示蛋形。切换、下载与生成失败不能使伙伴区域空白，也不能以损坏的新资产抹掉可用形象。

生活空间中的伙伴位于房间背景里，不叠加第二具活动立绘；衣橱独立预览除外。工作台内嵌伴工精灵。打开这两个入口时桌面精灵收起，完整窗口分工见 §6.1。

身份确认后的锁定与允许的外观变化见 §5.4；切换显示模式不等于重新定义伙伴。

## 2. 动画状态机

本节描述用户感知到的状态与过渡；状态标识、优先级实现和恢复规则见 [renderer README §6](../client/renderer/README.md#6-角色呈现契约modulescharacter)。

### 2.1 四类触发源

1. 日常状态：启动、断连、输入、思考、语音播放与工具执行产生对应反馈。
2. 情境表达：伙伴结合情境决定表情和动作，仅在允许自主表达时出现，不依附聊天正文。
3. 直接交互：戳、拖拽和悬停立即获得视觉反馈；需要推理的口头反应可稍后到达。
4. 空闲微动：眨眼、呼吸、观察等持续维持生命感，不因此发消息或出声。

### 2.2 切换规则（架构级）

持续状态按断连、交互、工作、说话、思考、倾听、情绪、空闲的优先顺序呈现；情绪与交互可作为短暂反馈插入，结束后恢复仍有效的状态。状态过渡应平滑，不能因低优先级更新让正在说话或工作的伙伴突然发呆。

### 2.3 2D 路径下的多层动画叠加

自然度是扩展动作的前提。验收连续运动中的关节轮廓、手型、遮挡、身份一致性与进出动作过渡；仅肢体连通、末端到达目标或静态截图合格均不足以通过。素材不支持自然动作时，应先完善素材或呈现方案。

- 转头时视线先行，头颈与身体协调跟随；面部五官和头发保持合理遮挡。
- 行走时脚部接地、手臂自然交替摆动；停止后平滑回到站姿。
- 拖拽时身体围绕抓取点轻微摆动，松手连续回正；扶边时双手与边缘接触稳定。
- 呼吸、眨眼、发束与裙摆微动可以叠加，但不能覆盖当前手势或破坏接触姿态。
- 说话嘴型跟随实际声音，停声后恢复自然状态；无声时不继续表现为正在朗读。

几何、动作互斥、素材降级和确定性验证见 [2D 渲染说明](../client/renderer/modules/character/rendering/2d/puppet/README.md)。

## 3. 空间行为与移动

位置、移动方式与形象状态分别表达“在哪里”“怎么过去”和“在做什么”，组合后应保持可理解的连续行为。

### 3.1 三轴：位置 × 移动方式 × 缩放

- 位置包括用户设定的栖息地、工作窗口旁、漫游途中与任务目标旁。
- 移动可表现为行走、快走、飞行、跳跃或用户拖动。
- 显示比例以用户设置为基准，必要时适应空间和表达，变化过程平滑。

### 3.2 场所与贴边吸附

用户拖放设定的栖息地跨重启保留；陪工、漫游与任务目标旁的位置都是临时位置。

拖到屏幕左右边缘附近释放时，伙伴可让身体大部分隐到屏外，探头向内看，双手扶住边缘。拖走或点击露出的部分会解除吸附并平滑返回安全位置；悬停不解除，避免用户在边缘作业时误触。具体触发距离与几何比例由渲染实现维护。

### 3.3 移动、物理反馈与缩放

拖拽松手后就地成为新栖息位置，空中释放同样适用。缺少形象资产时，蛋形仍能通过移动和浮动给出反馈。

默认显示比例可在设置中调整，范围为 0.3×–3×。窗口旁空间不足时等比例缩小；特定情绪下可短暂放大，结束后恢复默认。静止档不主动放大，空间适应也不能把伙伴压成不可辨识的小点。

### 3.4 四类移动触发源

1. 引导与屏幕布局变化：安排初始位置，拔屏或分辨率变化后保持伙伴可见。
2. 活动情境：自主档下根据工作窗口与桌面空闲状态决定陪工或漫游。
3. 用户任务：执行界面操作前，可先走到目标旁，见 §3.6。
4. 用户拖拽：立即接管位置，取消正在进行的自动移动。

### 3.5 打扰档位下的空间策略

| 档位 | 自动空间行为 |
|---|---|
| 自主 | 允许窗口旁陪工、漫游、走过去搭话与情绪放大 |
| 常规 | 停留原地，不主动换位置，停止正在进行的漫游 |
| 静止 | 停止自动移动，保持栖息位置，用户仍可拖动 |

档位只约束主动行为；用户请求触发的任务动作仍可执行。桌面精灵收起或锁屏时省略仪式行走，任务照常进行。档位生效条件见 §6.2。

### 3.6 仪式性行走（Ritual Walk）

用户请求打开应用、点击控件等界面操作时，伙伴可先走或飞到目标旁，沿途注视目标，抵达后指向并完成操作，再回到原处。这让用户能看出伙伴正在帮助自己。

目标不明确、不可达或行走失败时，以可理解的反馈退回普通工具执行，不阻断任务。视觉仪式不能重复实际点击。视线与指向应先于接触建立空间关系；用户打断后不能继续悬留旧目标的注视。

### 3.7 不变量与反模式

- 用户拖拽或点击可以打断自动移动；避免频繁走动或挡住正在使用的界面。
- 角色可见身体在垂直方向保持完整；只有左右扶边时允许部分身体隐于屏外。素材的透明留白不算身体。
- 桌面精灵保持置顶，用户全屏应用除外；移动与窗口切换不应造成置顶状态闪变。
- 除调试、全屏或屏幕布局恢复等必要情况外，不用瞬移代替过渡。

## 4. 伙伴生命周期

安装后以蛋形常驻 → 用户定义角色 → 确认头像、全身种子图、全身立绘与音色 → 孵化默认 2D 形象 → 初次问候 → 持续陪伴。生活空间承载情感与记忆，工作台承载专业任务。

房间生成失败不阻断孵化和问候。3D 在设置中按需升级；详细首次使用流程见 §5。

## 5. 初始化与 Onboarding

首次使用以对话认识伙伴，避免让用户面对技术配置表。

### 5.1 蛋阶段（Egg）

安装后以统一蛋形出现在桌面，用户唤醒后进入角色定义。

### 5.2 对话式信息采集（3 子阶段、13 步骨架）

角色定义先完成，再确认形象、音色和用户信息，避免中途切换主题：

- 角色七问：名字 → 物种 → 性别 → 基础形象 → 关系定位 → 性格 → 说话风格。
- 音色一问：形象确认后描述希望的声音，再试听选择。
- 用户五问：称呼 → 性别 → 年龄段 → 爱好 → 其他希望伙伴知道的信息。

问题同时提供文字和预制语音，可返回修改，非必填项可跳过；名字、物种与说话风格必填。基础形象可同时提供文字和参考图。关系定位影响相处方式，不替代性格与外貌定义。

多数标签直接代表答案；称呼页的“名字 / 昵称 / 称号 / 自填”只选择称呼类型，随后仍需收集实际称呼，不能把标签本身保存为名字。

每个非空回答即时保存，中断后恢复角色、形象和音色的未完成步骤。用户五问在首次流程中依次询问，但不作为重启后的完成门槛；跳过或遗忘后可在记忆管理页补填。角色定稿不等于引导完成：形象尚未确认时回到确认步骤，完成后继续音色与当前流程的用户信息收集。全身确认后后台生成形象，用后续对话吸收等待时间。

### 5.3 孵化与头像获取

角色七问完成后，用户可按描述生成头像，也可直接上传已有头像。说话风格随角色定稿，后续可在角色管理中调整。

生成失败显示友好反馈并有限重试，最多三次；仍失败时提供稍后重试入口，不把原始错误呈现给用户。

### 5.4 形象确认（头像与全身立绘）

头像支持确认、带反馈重新生成和自行上传。基础形象参考保留身份信息，额外风格参考只影响构图与表现形式；自行上传头像不能覆盖先前的身份参考。

头像之后生成全身种子图，完整展示身材、比例和整体气质，姿态自然优美、不要求固定站姿。引导沿用用户上传的参考图，也可更换或移除；用户可放大查看、提出微调要求并重新生成，确认后继续全身立绘。设置的“角色与记忆”提供同一入口，支持选择参考图并重绘；失败时保留已有预览，图片加载失败可单独重试加载。

随后由全身种子图派生正面全身立绘并确认：默认日系赛璐珞画风与自然站姿，无需先选择画风。画幅随物种适应并保持稳定，确认页完整显示图片，允许微调。未确认立绘作为草稿保留，中断后恢复已有草稿；超过保留期才重新生成。

全身确认后锁定头像、物种、性别与基础外貌，关闭身份重新生成入口。名字、性格、说话风格、关系、音色与用户信息仍可编辑。涉及锁定内容的引导步骤应提前说明不可更改的后果，不能等确认后才告知。

全身种子图重绘保留头像身份与角色定义，用于后续出镜参考；换装只改变服装、发型和配饰；首次 3D 升级使用独立确认流程。这些操作不意味着解锁身份。

### 5.5 渲染模式

首次引导生成 2D 动画形象，不展示模式选择。生成失败时保留蛋形并提供重试，降级规则见 §1.2。

首次在形象设置选择 3D 时，生成并确认适合立体建模的正面立绘，可微调；支持背面参考时再确认背面，背面失败可只用正面继续。类人角色采用二次元游戏画风，非人角色采用写实画风；具体姿态约束见 [PIPELINE](PIPELINE.md)。

3D 准备与生成期间有明确等待反馈，不覆盖已确认的 2D 形象，切回 2D 可立即继续陪伴。

### 5.6 音色子阶段

先描述希望的音色，再从当前语言可用目录中试听选择：

- 推荐卡说明声音特征，支持试听和换一个推荐。
- 完整目录包含支持当前语言的多语言音色，选择即可试听。
- 用户确认后保存声音；本页不重复展示已经确认的头像。

之后可在音色设置重新选择，或通过描述创建专属音色。

### 5.7 形象资产生成与最终孵化

全身确认后生成 2D 动画形象，并行准备初始房间。形象就绪后开始自然待机，用用户确认的声音给出初次问候。

房间未就绪或生成失败时使用可读的玻璃底和友好重试提示，不延迟伙伴诞生；不可用形象按 §1.2 降级。

## 6. 持续陪伴交互

### 6.1 双入口窗口架构与交互范式

生活空间与工作台是两个互斥的完整入口；轻语是在桌面精灵旁快速回复的浮层。对话负责交付文字、图片、视频和语音，片刻是精灵主导的朋友圈式时间线与回忆入口。

| 入口 | 定位与布局 | 伙伴呈现 |
|---|---|---|
| 轻语 | 默认 380×540 的可拖动玻璃卡片，含拖拽条、关闭按钮、陪伴消息与输入 | 精灵留在桌面，卡片默认靠其右侧 |
| 生活空间 | 默认 1080×720，房间全景、240px 左栏身份导航与轻透内容区 | 角色位于背景画面，桌面精灵收起 |
| 工作台 | 内嵌伴工精灵、会话侧栏、对话区与可折叠运行轨迹栏 | 精灵与工位组成整体，拖动时同步移动 |

打开生活空间或工作台会收起桌面精灵和轻语，暂停桌面自主走位；关闭完整入口后在原位恢复。关闭工作台不停止已经执行的本机工具。窗口切换不搬移陪伴与专业会话的上下文，预设隔离见 §8。

入口操作保持一致：双击精灵切换轻语；单击身体和头部触发直接交互；托盘主按钮打开上次完整入口，右键菜单提供两者入口。生活空间底部可去工作台，工作台可回房间。消息提醒按所属会话打开陪伴入口或工作台，不能把工作消息送进陪伴上下文。

生活空间的关键体验：

- 角色只出现在房间背景中，衣橱预览除外。背景极慢移动、玻璃高光、头像光效与生成等待时的呼吸底共同提供生命感；降低动态偏好时让背景平滑定格。
- 左栏按大圆形头像、居中名称、独立心境短语排列，再提供对话、衣橱、形象、片刻、日记、通道和设置。心境来自真实推理，无结果时不填造句或重复系统状态；“陪伴中 / 忙碌中”另作运行状态展示。
- 陪伴页固定使用唯一主对话，不提供新建和切换会话。工具执行过程不出现终端原文、参数、调用徽标或过程旁白。
- 房间支持手动更换及回滚最近五张历史。可在房间页选择参考图并填写布置或姿势要求，也可在对话中发图提出要求；参考图可以带人，精灵可模仿其姿势，同时保持自己的身份和当前穿着，成品中只有精灵本人。生成期间保留当前房间，失败可带原要求重试。锁定后禁止自主换房，仍响应换装联动和用户请求。
- 衣橱优先展示本机缓存，再同步云端。就绪外观可独立播放、暂停、重播并预览左右扶边；取景框边缘模拟屏幕边缘，不改变当前穿着或桌面行为。降低动态偏好下默认暂停；草稿仍显示立绘，缺姿态和加载失败提供明确说明与重试入口。
- 衣橱锁定时只响应用户操作；解锁后伙伴可在夜间选穿就绪外观，或因明确情境设计新装，完整就绪后才穿上。

工作台强调任务信息密度：会话侧栏、中间对话与工具记录、右侧运行轨迹分别承担导航、交流和执行详情。轨迹展示工具、终端、代码差异与产物，不重复对话正文；推理过程在助手消息内折叠查看。

工位设置按推理与对话、本机执行器、技能与工具集分区，打开时遮住底层对话与输入，避免重叠透底。输入区空闲时紧凑，聚焦、有附件或多行输入时展开；生活空间保留短小的陪伴输入。

视觉样式共用夜色、日色、夜色透明、日色透明四档，新装默认日色透明。样式只改变界面，不改变伙伴形象。实底档保持完整底板；清透档以低填充玻璃、细描边与内高光成形，避免乳白底遮住房间。左栏与窗壳连成一体，生活空间更透，工作台底板更实以保证代码可读。右键菜单独立保持可读底色。

两端对话与消息操作：

- 生活空间显示自然聊天，不显示推理；默认文字模式提供轻量朗读按钮，始终语音模式显示语音条与折叠文字。工作台只显示文字、工具和推理，不展示语音条或朗读按钮。
- 用户消息操作在悬停时出现：陪伴页提供撤回，工作台提供撤回和派生新对话；工作台助手消息也可作为派生起点。
- 图片和视频以内联卡片展示，点击放大或播放；对话窗外的提醒只承载简短文字与查看入口。未读跨重启保留，进入所属会话才清除，提醒消失不算已读。
- 时间分隔条采用本地时区和 24 小时制。首条消息显示时间，之后相邻可见消息间隔至少五分钟才新增；当天显示时分、昨天带“昨天”、七天内带星期、今年更早显示月日、跨年带年份。居中小字无胶囊底，不写进正文。
- 响应模式仅作用于陪伴：默认文字不自动出声；始终语音在准备时显示等待提示，就绪后自动按序播放，文字可展开。点其他语音条会抢占，停止或发送新消息会打断。历史按当前模式显示，主动陪伴语音另受 §6.2 约束。

### 6.2 主动陪伴与打扰档位

陪伴型定时任务进入唯一主陪伴对话；普通自动化使用独立任务会话和系统通知。打扰档位控制在线实时主动行为，不限制用户发起的对话、戳摸、任务请求、普通自动化或夜间离线整理。

陪伴任务先安静判断是否适合开口，这期间不显示思考、打字或工具活动，也不向历史写入触发指令。保持沉默时界面与消息历史均无变化；决定开口时才记录自然台词，提醒和语音按档位显示。

伙伴可以保存有明确目的的后续安排，等约定时间到了或相关桌面情境变化后再考虑继续交流。等待时不持续思考，沉默也可以保留后续安排；没有新的理由时结束这一项意图，不因用户未回复而循环催促。离线、锁屏或静止时等待暂停，有效期结束后不补发过时内容。重新连接和解锁本身不自动生成问候，只能唤醒已有安排。

用户发言优先于尚未交付的主动表达，并可在后续对话中修改或取消等待。伙伴只把已确认成功的行为当作进展；执行中断且结果不明时，先核对结果，不重复执行后宣称成功。

| 档位 | 在线主动行为 |
|---|---|
| 自主 | 文字、语音、桌面情境动作与移动，以及完整房间布置和生活记录 |
| 常规 | 原地轻量文字、少量生活片刻与轻量房间装饰；装饰每 24 小时最多成功一次，无主动语音、视觉表达或移动 |
| 静止 | 不发起主动推理、跟进、换房或记录，仅响应用户交互 |

手动静止不被活动覆盖。游戏、全屏等沉浸场景临时进入静止；写作、阅读等专注工作沿用用户选择。静止须从源头停止主动判断，不能只是把生成的结果静音。用户聊天后的心情维护仍正常进行；锁屏时停止主动提醒，解锁后安静恢复。

常规档下约一小时没有聊天或戳摸、且没有正在进行的主动节奏时，可结合粘人型人格判断是否发一条简短问候；每次仍由伙伴按情境决定，不形成必发话术。

夜间整理由夜间总控及房间、衣橱、媒体、语音政策独立控制。伙伴可结合记忆、重要日期与近期经历选择少量有理由的活动，也可什么都不做。换装成功后再生成匹配房间与出镜媒体，新装未完成时保留旧装及匹配房间；语音使用当前音色。只有成功发生的活动进入日记、片刻与后续问候，不能把计划说成经历。一个活动失败不应阻断其他可完成活动，夜间更新不弹实时通知。

夜间总控关闭时全部跳过，各能力关闭或不可用时仅跳过相应活动；开始活动前重新确认政策，避免采用已失效的许可。夜间房间活动与在线布置分别限额。没有前一日对话仍可根据长期重要日期准备心意，但不能伪造新经历。次日问候只在用户在线且非静止时送达，最晚保留到目标本地日结束，夜里准备不意味着白天必然打扰。

桌面自主动作的条件和体验见 §6.4。

### 6.3 用户直接交互（戳、拖、悬停）

戳、摸头、连续戳击、长按、拖拽、悬停与右键应有可区分的反馈。直接交互不受主动打扰档位限制，具体手势识别见 [renderer README §6](../client/renderer/README.md#6-角色呈现契约modulescharacter)。

- 戳击按频率分轻、中、重反馈，连戳至少五次出现怒气十字，至少八次进入眩晕并显示星环；停手后恢复。口头反应结合角色性格和实际交互产生。
- 头部或刘海区域在半秒内至少两次横向转向视为抚摸，表现轻蹭、眯眼与爱心反馈；单击头部同样走摸头。声音与文案遵循下述智能反应及降级开关。
- 外部文件拖入精灵时显示接取与爱心或音符反馈；纯图片、视频进入轻语，混有其他文件时整批转到生活空间。
- 拖拽表现轻微惯性与悬挂，松手后在原地站稳并定居；移动与扶边规则见 §3。
- 悬停时视线跟随，头发或裙摆可有轻微物理反馈；不因悬停解除扶边。
- 右键菜单提供生活空间、工作台、免打扰、归位与隐藏入口；点击外部、失焦或按退出键关闭，关闭动作不能误触戳击或拖动。
- 生活空间打开时直接交互转到左栏头像，提供轻量状态与短语反馈，不操纵已经收起的桌面精灵。

智能反应关闭、冷却、限流或失败时，可回退预制的性格化反馈，不冒充实时推理。戳摸推理有五分钟成本限制，超出后保留即时本地反馈；戳与聊天的互动统计仍记录。拖拽始终使用机械动画与预制语音，不调用推理，也不计入戳摸统计。

以下开关独立控制，默认开启：

- 戳智能反应：决定戳摸是否优先使用情境推理。
- 空闲情境表达：决定自主档下是否产生独立的桌面表情和动作。
- 自主空间行为智能驱动：开启时由伙伴决定是否移动，关闭时使用本地空间规则。
- 夜间自主心意创作：控制夜间图片和视频，不影响文字片刻、换装、房间与问候判断。
- 夜间自主语音心意：控制语音片刻与媒体配音，关闭后视觉媒体仍可无声生成。

### 6.4 自主行为（让形象“活着”）

空闲微动作只提供视觉生命感，不发消息或出声。观察时左右看、抬头或低头，动作间回正，与自然呼吸、眨眼和发饰微动协调。

情境视觉表达和空间智能行为要求自主档、桌面精灵可见且屏幕解锁。生活空间或工作台打开、桌面精灵收起时停止咨询；情境表达还需满足空闲条件。表情和动作只能使用当前形象能自然呈现的能力。

空间智能驱动开启时，伙伴结合空闲、时间与工作场景选择陪工、漫游、走过去搭话或不动；决定不动或推理失败时保持静止。关闭时使用本地规则陪工与漫游，本地规则不生成开场白。

走过去搭话保持低频，两次至少间隔三十分钟；伙伴边走边说，在工作窗口旁或桌面中下部停留。说话仍是独立的自然台词，不把动作描述塞进聊天正文。

### 6.5 故障态与降级行为（伙伴永不“死”）

故障应让用户理解伙伴暂时遇到困难，并提供可操作的恢复方式，不暴露原始错误。人格化台词仍遵循表达生成边界，无法推理时使用已约定的机械降级或客观系统提示。

| 故障 | 用户感知与恢复 |
|---|---|
| 云端断连 | 打盹或走神；用户等待回复时较早反馈，后台抖动给予更长宽限 |
| 本机执行器不可用 | 陪聊正常，用户要求操作时如实说明暂时无法执行 |
| 形象生成或加载失败 | 按 §1.2 显示可用形象或蛋形，提供相应重试 |
| 登录、权限等需要用户处理的问题 | 清楚说明问题并提供操作入口 |
| 语音不可用 | 保留可读文字；听写失败允许改用输入 |

重连时从走神平滑恢复，不主动补一句台词或触发语音。工具失败应诚实说明没有完成，不用角色表演掩盖失败。开发者视图可查看诊断细节，普通界面保持可理解的反馈。

### 6.6 对话节奏与状态分离

| 表达 | 触发与表现 |
|---|---|
| 聊天正文 | 只包含可阅读、可朗读的台词，显示为气泡并按模式朗读 |
| 当前心情 | 用户发起的生活空间陪伴回合后独立更新；直接互动也可更新，显示在身份区，不生成消息 |
| 桌面视觉表达 | 满足自主条件时独立驱动表情和动作，不进入聊天历史 |
| 桌面空间行为 | 独立决定陪工、漫游、靠近或静止，位置服从桌面环境 |

聊天和主动问候均不夹带控制标签、第三人称动作旁白或纯动作回合。声音表达不等同于当前心情，完成回复也不附带桌面动作指令。

陪伴等待完整答复确认后再按气泡节奏交付，文字与语音模式采用相同分段。查询和操作期间生成的临时台词不显示、不朗读，避免先说一小段又重复说完整版；允许多等待一会儿，以保持表达完整、自然。工作台边生成边显示，过程说明与最终答复分开，历史保留最终答复和工具记录。

- 伙伴可连发多条短回复，逐条显示并留短暂停顿；分段只改变呈现，历史仍属于同一轮答复。
- 用户连发时，发送后等待约四秒；继续打字、输入法组字或再次发送会重新计时。停止输入满四秒后合并已发送内容，只触发一次回复，未发送草稿不参与。
- 上一轮结束不能缩短等待；已到期批次等上一轮结束再提交。有输入时按钮用于发送，空输入时用于停止；主动停止会立即提交已经排队的消息。

协议、分段和语音交付约束见 [PROTOCOL §1.4](PROTOCOL.md)。

### 6.7 跨端陪伴：外接 IM 通道（微信 / QQ）

外接 IM 延续同一伙伴身份和陪伴记忆，各渠道保留自己的对话历史，不把这些经历带入专业工作会话。具体已接入渠道及限制见 [PROTOCOL §1.7](PROTOCOL.md)。

- 桌面关闭时仍可陪聊；请求本机操作时电脑必须在线，否则如实告知无法触达。
- IM 发起的本机操作保持安静，不切换桌面工作状态或向桌面对话插入过程；结果可在对应 IM 会话历史中只读回看，桌面不能代发。
- 发起任务的人可明确喊停，停止不受普通消息限流排队阻碍，丢弃后续排队消息并回复确认；否定句或含相似字词的日常句子不能误触。已经交给本机执行的当前步骤不会撤销。
- 默认拒绝陌生对端，首次来信给一次配对提示，主人批准后才可对话，被拉黑者静默。审批界面必须说明：批准意味着允许其操作这台电脑。
- 微信仅回复入站消息，不主动发起陪伴；主动陪伴保留在桌面。回复按渠道使用纯文字或受支持的媒体，不镜像桌面动作；执行期间可显示正在输入，完成后再交付答复。

## 7. 语音交互

语音输入与输出由云端提供，任何语音环节失败都不阻断文字交流。首次引导的预制语音属于 §5 的独立流程。

伙伴结合当前声音能力决定情绪、语调、语速和必要的句内声音；支持精细演绎时协调气息、重音与情绪起伏。语气词克制，不机械复制用户情绪；聊天、复制与转写只呈现台词。历史朗读保留原回复的表达意图。

陪伴响应模式见 §6.1，主动语音的打扰边界见 §6.2；供应商与录音限制见 [backend README](../backend/README.md)。

## 8. 多预设并列的系统对话

引导完成后提供五个固定系统预设，不可删除或改名。它们共享伙伴的视觉身份，但各有独立历史、长期记忆和画像；陪伴人格与情感只用于陪伴目标。

| 预设 | 使用目标 |
|---|---|
| 陪伴 | 角色化日常交流，结合穿着、关系、时段、发言间隔与陪伴记忆 |
| 开发工程师 | 遵循项目约束进行解释、设计、实现与调试，以证据审查问题并说明验证结果 |
| 产品经理 | 从用户问题和成功标准出发，以证据权衡方案，明确范围、依赖与验收条件 |
| 文案秘书 | 保留事实、语气与意图，交付可用成稿，整理邮件、报告与会议事项 |
| 语言老师 | 按目标和实际水平讲解、纠错与练习，提供忠实自然、符合用途的翻译 |

专业预设按当前任务决定回答深度，已有信息足够就推进；关键缺失才询问。产品分析只在存在实质取舍时比较方案，文案默认交付一版成稿，翻译默认给自然译文；多版、直译对照与练习按需求提供，不成为每轮固定负担。语言教学可用易懂的语言讲解并用目标语言练习，不要求先填写等级，也不因一段外语材料就强制全程切换语言。

陪伴独占生活空间和轻语；工作台置顶其余四个专业预设，并展示用户自建及任务派生会话。新建工作对话只能选择专业预设。切换工作与生活入口不改变伙伴身份，也不合并两端历史。

特殊会话按场景提供温度、压缩阈值和推理强度默认值，只在自己的窗口修改或恢复默认。工作台全局设置只影响没有相应会话覆盖的普通对话；普通对话使用预设模板也不改变其设置归属。

伙伴自主维护有证据的长期记忆：明确长期要求可立即记住，临时情绪或一次上线不自动成为偏好，用户纠正应覆盖旧判断。候选、失效与过期记录不参与互动。

管理页显示所选预设、记录状态及依据，用户可编辑或删除；引导时收集的个人资料在陪伴预设的管理页中补填、修改或删除，删除后仍可重新填写。切换预设同时切换列表、数量、筛选与编辑状态，迟到的旧结果不能重新覆盖页面。管理其他预设不意味着当前对话可读取其记忆；已有消息的会话不能直接换角色，应进入目标会话或新建空会话。

夜间整理同样按预设隔离：专业会话只沉淀本域事实与偏好，陪伴反思、情感、日记和主动规划只依据陪伴经历。

## 9. 记忆产品化——片刻与日记

### 9.1 底层检索与叙事呈现解耦

用于延续交流的检索记忆保留有依据的事实、偏好和经历；普通闲聊不必逐条存成记忆。用户无需理解向量或检索机制，管理体验见 §8。

片刻与日记是面向用户的生活记录，用伙伴视角呈现情绪与经历；它们不能反过来成为用户偏好的独立证据。

### 9.2 生活片刻（Moments）：精灵主导的朋友圈

片刻以短标题、正文、情绪和可选配图按时间倒序呈现，类似朋友圈：每一条都由精灵主动发起，用户不发布、不编辑。精灵何时发、发什么由其结合心境、记忆与近期互动自主决定，产生通道有三：白天低频自主冲动（默认每天至多 3 条）、聊天中随手写下的感悟（每日配额约束）、夜间整理时准备的心意（文字、图片、视频、语音与房间布置）。系统不再为诞生、换装、房间变化等节点自动生成片刻，普通闲聊也不批量转成片刻；专业工作会话只积累自己的工作记忆，不向生活空间写入生活片刻。

用户可以在单条片刻下评论并得到精灵的回复，这些互动会作为当天经历进入夜间的规划、反思日记与日记投影，影响精灵后续的表达与心意。用户不能修改精灵的内容，但可以隐藏整条片刻、删除自己发出的评论。

### 9.3 第一人称日记（Diary）：自然日的心灵沉淀

日记按用户本地自然日归集，原则上每天一篇，以月历和图文详情浏览。休息时段结合当天陪伴经历、记忆和片刻整理，不能虚构未发生的活动。

用户可随时补写或编辑。用户编辑过的日记不被后台覆盖，新内容只能追加。日记生成与更新保持静默，等待用户主动查看。
