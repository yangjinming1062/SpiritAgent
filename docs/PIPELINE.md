# 形象生成能力链

本文维护参考来源、2D / 3D 能力编排、产物和失败恢复。

<a id="1-3d-链拓扑"></a>

## 1. 参考与派生关系

```text
角色定义 + 已确认头像
          ↓
    独立全身种子图
      ├─ 2D 正面立绘 → 分层 PSD + 左右扶边姿态 + 闭眼附件
      ├─ 3D 正面种子 → 可选背面种子 → 生模 → 可选绑骨 → 可选动画
      ├─ 换装草稿 → 确认 → 新 2D 完整包
      └─ 房间、自拍与其他出镜媒体
```

### 1.1 共用参考与种子图派生

| 输入或产物 | 必须保持的语义 |
|---|---|
| 头像 | 锚定身份；关系定位只影响交流，不作为外貌属性 |
| 独立全身种子图 | 由头像与角色定义补全身材比例；姿态自然，不直接提交 2D 拆分或 3D 生模 |
| 2D 正面立绘 | 从全身种子图派生，2D 专用动漫插画画风（`anime_2d_illustration`）、自然站姿；确认后作为 2D 重切分来源 |
| 3D 正面种子 | 从全身种子图独立派生；双足使用 A-pose，画风按物种路由（类人精绘 / 非人写实）；不覆盖 2D 立绘 |
| 3D 背面种子 | 与正面配对；重绘 3D 正面使旧背面失效；背面失败可退回单正面提交 |
| 换装草稿 | 全量重绘始终以独立全身种子图锚定身份与身材，不反复引用旧外观造成漂移 |

非双足姿态按骨架采用自然站立或舒展，不机械套用 A-pose。画风与姿态分别决定；提示词只写宽高比，像素尺寸由请求与供应商实现决定。

带图提示词按输入用途表达任务：头像补全全身、原图角色调整视角或姿态、换装、进入场景、局部编辑分别明确允许改变的内容，保留原图已确定的角色特征。内部生成与自备图共用派生模板；2D / 3D 按链路调整画风，背面按正面结构补全，不镜像正面。上传头像附带风格参考时，主体图确定角色，风格图只提供呈现方式；双图经左右拼图传输，提示词按图 1 / 图 2 说明分工。

用户服装参考图先与文字整合为着装描述，不直接作为换装生图的身份参考；整合失败可按纯文字生成。房间和出镜媒体必须取得可读的全身种子图，缺失时停止并提示修复。

房间以全身种子图确定身份和身材，以当前着装描述确定穿着；用户场景图只提供布置、氛围、构图及明确要求的姿势，不引入额外人物或改变身份。文字要求优先于场景参考，场景参考优先于默认布置。

普通对话的 `subject='self'` 图片使用独立全身种子图作身份参考，视频以该图为首帧。夜间出镜图片另按可用性带入当前外观参考；夜间出镜视频仍使用全身种子图并保留图中穿着，不能用于承诺展示刚换上的衣服。夜间媒体的 `narration` 生成独立音轨，不保证视频口型同步。

全身种子图重绘成功后才替换旧图，不自动重建既有 2D、3D 或房间资产。换装后的房间着装一致性另按 [PROTOCOL](PROTOCOL.md#12-伙伴生命周期方法方法级契约) 处理。

### 1.1.1 图像修改双模式（微调 / 重新生成）

`mode` 缺省为 `regenerate`，按各点位固定参考全量重绘。`edit` 使用上一版产物作为编辑底图，只改变反馈指定部分，必须同时满足：反馈非空、旧图存在且可读、未附加参考图、供应商声明并实现图像编辑能力。

编辑条件不满足时明确失败，不能静默改成全量重绘。身份条件化参考不等同于图像编辑能力；具体能力位与路由见生成模块。

### 1.1.2 用户自备图

用户获取完整提示词，并用客户端本地缓存的种子参考图在外部工具生成后上传采纳。提示词以参考图锚定身份；各点位参考图与 AI 生图同源：全身参考用头像种子，2D / 3D / 换装 / 房间用全身种子，背面用 3D 正面种子，单侧姿态用当前外观正面立绘。提示词不引用产品内部概念或供应商专有参数；采纳进入与正常生成相同的确认、存储、事件和激活流程。2D 点位（2D 正面 / 换装）提示词固定为动漫插画画风；写实或照片级成品会因 see-through 动漫域限制明显劣化（见 [§6.1](#61-psd-链see-through-双-provider)）。

对应参考图在 onboarding 后恒在：提示词与 AI 路径都必须带参考图，缺失或不可读时同样明确失败。外观一致性由用户确认，不宣称程序完成身份验证；自备图不区分微调与重新生成。单侧姿态提示词直接包含真实 Alpha 透明背景要求（完整生成契约见 [§6.2](#62-扶边姿态包)）；客户端在自备图入口说明需使用支持透明输出的生图工具并保留 PNG 原件。上传后按实际透明通道判定：自带可用透明背景的图保留原始 alpha 跳过后端抠图，其余图仍走混合抠图，之后同样经过定位和闭眼附件处理。

换装确认接口可选携带左右姿态图：对应侧在切分管线中跳过 AI 姿态生图，直接进入既有后处理；未提供侧仍走 AI。确认请求在启动切分前校验姿态图可解码，失败不启动管线（客户端仍持有原图）。已通过校验的姿态图在进程内按外观暂存：切分失败后的重试确认与同进程恢复未再次携带时自动复用；切分成功或删除外观时清除。进程重启后暂存不保留，恢复切分可能退回双侧 AI 生成。设计草稿阶段即可取单侧姿态提示词；就绪外观仍可单侧重生成或自备图替换。

房间获取提示词时创建 `source=user_upload` 的 pending 行，不启动 AI 生成，也不被生成恢复程序误启动；采纳进入 ready，放弃进入 superseded。

### 1.2 3D 阶段与持久化

各阶段通过供应商任务 ID 串联，最终 GLB 下载落盘。缺少绑骨能力或绑骨失败时可交付基础模型；只有绑骨成功、支持动画绑定且动作集合非空时才进入动画阶段。

动作映射只在动画绑定实际成功后持久化。空映射表示不承诺动画，不能用声明的能力代替真实产物。

## 2. 能力声明

[ImageTo3DProvider](../backend/services/infrastructure/image_to_3d/base.py) 定义生模、轮询、下载和可选能力。多视角、绑骨、动画及负面提示词能力必须与实现一致；不支持多视角时只提交正面图。

供应商 token、骨架命名和请求参数留在适配器，客户端只消费统一资产与语义动作映射。不为缩短接入流程而把供应商命名复制到渲染端。

## 3. 失败与重试语义

| 状态 | 处理 |
|---|---|
| 未配置供应商 | 提示配置，不进入生成 |
| 有任务 ID，供应商已成功 | 恢复后续阶段或下载，不重做已确认阶段 |
| 有任务 ID，仍排队、网络异常或结果未知 | 保留任务并核对，不盲目重新提交 |
| 供应商明确终态失败 | 可由用户重新生成；是否再次计费由供应商决定 |
| 下载失败且已有可恢复任务 | 提供“重试下载”，不替换成“重新生成” |
| 缺少可恢复任务句柄 | 不能宣称能接续既有付费任务；按失败状态向用户提供处理入口 |

生模句柄在提交后、轮询前保存；绑骨和动画句柄当前在各阶段成功后才更新。提交至保存之间仍有崩溃窗口，恢复可能重复提交某一跳。供应商任务和下载地址也有外部保留期，因此不能承诺绝不重复计费或永久可恢复。

新生成使用独立记录，就绪后形成唯一激活模型；当前实现发起新生成时会解除旧记录激活态。客户端保留已有可用呈现的体验要求，不等于数据库始终保持旧模型激活。非强制请求可复用有效模型，避免无意重复生成。

## 4. 3D 产物契约（Tripo3D `spec=tripo`）

当前 Tripo 链使用 `spec=tripo`。骨骼命名规范与绑骨算法版本分别配置；改变其中任一项，都须检查绑骨、动画绑定及客户端引用，不能只验证生模成功。

实际预设与骨架映射见 [Tripo 适配器](../backend/services/infrastructure/image_to_3d/providers/tripo/client.py)。未绑定动画的骨架允许空动作映射；蒙皮辅助骨不直接作为动画目标，缺少面部骨骼不能被描述为支持完整面部动画。

## 5. 3D 客户端消费

`animation_clips(rig_type)` 定义语义键与供应商动作名称的映射；成功结果保存于 `clip_map_json`，随查询响应和 `model.ready` 交付。

客户端依次尝试候选全名精确匹配、去命名空间后的叶名精确匹配、叶名子串匹配。语义键缺失时先尝试 `idle` 映射；已有候选但匹配失败时不再额外尝试 `idle`。最终无匹配则保持绑定姿势，不报动画成功。

模型只接收可请求的语义动作，状态和交互专用动作不开放给自主推理。具体映射见 [AnimationMap](../client/renderer/modules/character/rendering/3d/AnimationMap.ts)。

## 6. 2D 分层动画能力链

### 6.1 PSD 链（see-through 双 provider）

see-through 分层拆分是面向动漫插画的扩散式分层生成模型，不是纯抠图：输出 PSD 的每个语义图层都由模型重绘并补全遮挡区域，且非方形输入会先被填充、画幅重采样到服务配置的分辨率。因此 2D 链的输入必须是动漫插画风格——写实或照片级输入会明显劣化（面部重绘发灰失真、五官塌陷），原图背景也可能被并入图层、随角色一起渲染到桌面。该域限制是 2D 链画风分槽的唯一依据：2D 正面种子的生成 / 确认 / 采纳、换装立绘及其自备图提示词，画风恒为服务端固定的 `anime_2d_illustration`（`MESH2D_STYLE`，定义见 [prompt_engineer](../backend/services/infrastructure/llm/prompt_engineer.py)）；3D 种子画风按物种路由（类人 `refined_anime_cg` / 非人 `realistic`），两条链不得为观感统一而重新合并。写实风格的角色呈现应走 3D 链。

拆分输出按候选分层处理：发布前由 [mesh2d/appearance](../backend/services/application/generation/mesh2d/appearance/README.md) 以标准化原图执行原图锁定重建（可见区域回填原图像素、生成内容仅保留在不透明遮挡补全区、按客户端运行时层序与 cleanAlpha 口径归属）并执行外观门禁——验收对象是重建 PSD 实际图层的重合成结果，与原图逐像素比较（全局与脸部 ΔE00、脸区连续异常色块、前景透明度与透明源孔洞、内部前景覆盖率），未通过不发布、不激活，保留上一版合格外观，诊断产物按任务隔离保留在 `appearance-trace`。拆分提交统一使用标准化原图重编码的 PNG（EXIF 方向已修正，自备图支持任意 PIL 可解码格式），提交 MIME 按文件魔数探测，下载结果校验 PSD 签名。

确认立绘并行进入分层 PSD 拆分和左右扶边姿态生成，两条分支完成后发布完整描述符、资产哈希及就绪事件。新外观完整就绪前不替换当前穿着；同用户激活资产受唯一性约束。

分层服务采用主备供应商和共享总预算，供应商内不无限重试。提交、轮询、下载、限额冷却与当前参数见 [see-through](../backend/services/infrastructure/seethrough/)。

PSD 持有语义图层及遮挡关系，客户端在装配边界解释部位、左右侧与肢体节段。素材完整度限制可用动作和形变幅度；几何与动画实现见 [puppet README](../client/renderer/modules/character/rendering/2d/puppet/README.md)。

### 6.2 扶边姿态包

左右姿态分别从当前立绘单张原图生成（或采用确认时提交的自备图，见 [§1.1.2](#112-用户自备图)）：角色身份与穿着只由原图提供，目标姿态、空间关系、构图和背景要求全部由提示词一次表达；不拼接任何指导图、骨架或遮挡板，不水平翻转成品，也不以已生成的一侧作为另一侧的参考。

姿态以观察者视角定义：左侧贴边时脸胸向右探出、前臂从右向左回扶，右侧贴边时脸胸向左探出、前臂从左向右回扶。腰背侧弯带动胸廓和肩部越过接触线，骨盆与双腿留在来源半幅作支撑；双肘位于探出半幅，双手在脸部靠来源侧的位置一上一下扶住同一条边缘。生成图保留完整角色，不绘制遮挡物，屏外隐藏由客户端兑现。画布横向中心只是接触线的生成目标，`contactX` 仍按生成图实测双手位置交付，双手明显偏离同一条接触线时素材按不合格拒绝，不做平移或拉伸修复。

背景策略在请求前确定：供应商链中存在已映射并经真实验证透明输出的配置时，走原生透明路径请求透明 PNG；否则使用同一姿态条款加色幕背景，经本地混合抠图交付，不计为原生透明。闭眼附件从对应主姿态局部编辑，沿用主图坐标与 Alpha，主图的透明能力筛选与闭眼编辑能力筛选分开。

描述符交付姿态纹理、接触线、头部、双手控制区及内容哈希。客户端按真实窗口边缘对齐接触线，局部微动固定双手，不能让接触点漂移。

资产门槛分为两类：可解码、非空、坐标有限有效、引用完整以及双手处于同一条接触线属于可加载约束；裁切、手型、朝向、色幕残留、闭眼效果和自然度属于视觉质量。当前自动流程不会因所有视觉瑕疵重绘或拒绝交付，可加载不代表体验验收通过。

旧包缺少有效双手控制区时，可以显示姿态和眨眼，但关闭探身形变；其他必要几何与纹理仍须有效。扶边纹理下载失败不清除已经装配的立绘。当前双手扶边要求不适用于所有多肢体或无手物种。

就绪外观可单侧重生成：只替换该侧姿态及描述符子树、重算整包哈希，PSD 与另一侧不变。任务与整包生成互斥，失败保留旧姿态和 ready 外观；单侧在途任务当前不持久化，进程重启后不能承诺自动续跑。

启动或读取资产不隐式补齐、重绘旧包。失败重试优先复用已有立绘；原图不满意时先修改并确认草稿，再生成新包。

## 7. 渲染与传输

3D 消费 GLB 与动作映射；2D 消费分层 PSD、描述符与按需加载的姿态纹理。签名轮换不代表内容变化，资产访问、缓存和恢复遵循 [PROTOCOL](PROTOCOL.md#15-资产-url-签名与传输缓存)。显示模式与降级顺序只在 [DESIGN](DESIGN.md#12-渲染模式与降级体系永不空白) 定义。

## 8. 按改动选择验证

参考与提示词变更检查身份、穿着、输入顺序及派生失效；编辑与自备图变更检查前置守卫和采纳后的状态一致性。供应商变更检查真实 GLB 或 PSD，不能仅凭能力声明通过验收。

恢复变更覆盖提交未落库、轮询中断、下载失败、未知结果及迟到结果；2D 变更覆盖单分支失败、旧外观保留、单侧替换和旧包降级。可加载性、视觉质量、模拟结果和真实供应商结果分别报告。

仅修改文档时核对事实与链接，不要求重新触发付费生成。验证入口见 [Scripts](../scripts/README.md)。
