# 形象生成能力链

本文维护参考来源、形象能力编排、产物和失败恢复。

## 1. 参考与派生关系

```text
角色定义 + 已确认头像
          ↓
    独立全身种子图
      ├─ 外观参考正面立绘 → 确认锁定身份 → 外观（着装参考）设计 → 视频动作包
      └─ 房间、自拍与其他出镜媒体
```

### 1.1 共用参考与种子图派生

| 输入或产物 | 必须保持的语义 |
|---|---|
| 头像 | 锚定身份；关系定位只影响交流，不作为外貌属性 |
| 独立全身种子图 | 由头像与角色定义补全身材比例；姿态自然 |
| 外观参考正面立绘 | 从全身种子图派生，固定动漫插画画风（`anime_illustration`）、自然站姿；确认后锁定身份，并作为外观设计与视频链的身份参考 |
| 换装草稿 | 全量重绘始终以独立全身种子图锚定身份与身材，不反复引用旧外观造成漂移 |

画风与姿态分别决定；提示词只写宽高比，像素尺寸由请求与供应商实现决定。

带图提示词按输入用途表达任务：头像补全全身、原图角色调整姿态、换装、进入场景、局部编辑分别明确允许改变的内容，保留原图已确定的角色特征。内部生成与自备图共用派生模板；外观参考与换装固定动漫插画画风。上传头像附带风格参考时，主体图确定角色，风格图只提供呈现方式；双图经左右拼图传输，提示词按图 1 / 图 2 说明分工。

用户服装参考图先与文字整合为着装描述，不直接作为换装生图的身份参考；整合失败可按纯文字生成。房间和出镜媒体必须取得可读的全身种子图，缺失时停止并提示修复。

房间以全身种子图确定身份和身材，以当前着装描述确定穿着；用户场景图只提供布置、氛围、构图及明确要求的姿势，不引入额外人物或改变身份。文字要求优先于场景参考，场景参考优先于默认布置。

普通对话的 `subject='self'` 图片使用独立全身种子图作身份参考，视频以该图为首帧。夜间出镜图片另按可用性带入当前外观参考；夜间出镜视频仍使用全身种子图并保留图中穿着，不能用于承诺展示刚换上的衣服。夜间媒体的 `narration` 生成独立音轨，不保证视频口型同步。

全身种子图重绘成功后才替换旧图，不自动重建既有外观或房间资产。换装后的房间着装一致性另按 [PROTOCOL](PROTOCOL.md#12-伙伴生命周期方法方法级契约) 处理。

### 1.1.1 图像修改双模式（微调 / 重新生成）

`mode` 缺省为 `regenerate`，按各点位固定参考全量重绘。`edit` 使用上一版产物作为编辑底图，只改变反馈指定部分，必须同时满足：反馈非空、旧图存在且可读、未附加参考图、供应商声明并实现图像编辑能力。

编辑条件不满足时明确失败，不能静默改成全量重绘。身份条件化参考不等同于图像编辑能力；具体能力位与路由见生成模块。

### 1.1.2 用户自备图

用户获取完整提示词，并用客户端本地缓存的种子参考图在外部工具生成后上传采纳。提示词以参考图锚定身份；各点位参考图与 AI 生图同源：全身参考用头像种子，外观参考 / 换装 / 房间用全身种子。提示词不引用产品内部概念或供应商专有参数；采纳进入与正常生成相同的确认、存储、事件和激活流程。外观参考与换装点位提示词固定为动漫插画画风，与形象参考链保持一致。

对应参考图在 onboarding 后恒在：提示词与 AI 路径都必须带参考图，缺失或不可读时同样明确失败。外观一致性由用户确认，不宣称程序完成身份验证；自备图不区分微调与重新生成。

外观确认接口不携带图片载荷：确认把草稿立绘转正为持久参考图（`ready`），只表示参考图就绪，不触发任何生成，也不自动穿着；穿着经激活接口显式完成。设计草稿阶段即可获取自备图提示词。

房间获取提示词时创建 `source=user_upload` 的 pending 行，不启动 AI 生成，也不被生成恢复程序误启动；采纳进入 ready，放弃进入 superseded。

## 2. 视频动作包链

视频包是同一外观的一组独立动作。参考图在建包时复制为不可变资产，指纹包含身份 ID、外观 ID 和参考图字节；全部动作及单动作重做都使用同一份参考。视频保留参考图的画风、五官、物种、身体比例、穿着与配色，不在视频阶段强制改为写实。共享参考约束生成输入，不能作为模型输出身份完全一致的自动证明，视觉一致性仍需逐动作预览。

### 2.1 逐动作生成

1. LLM 根据角色资料、性格标签、物种、外观描述和用户反馈，为请求动作编写起始姿态与一段动作描述，只表达可见的姿态、节奏和神态，不包含产品用途、镜头或背景要求。待机的性格差异主要体现在站姿：选定后身体几乎不动，只保留轻微眨眼和近乎不可见的呼吸，不安排手势、转头或重心变化。代码固定动作集合及各动作时长（待机一秒，其余两秒），脚本快照逐动作保存。
2. 图像编辑链从冻结参考派生动作关键帧，保持身份和画风；关键帧持久化后才提交视频，避免把短片大部分时间用于从站姿进入动作。
3. 编排层将 LLM 的动作描述与固定视觉约束组合为完整视频提示词：身份与画风保持、循环首尾一致、固定镜头、全身留白、原地运动及纯净静态背景；待机另约束站姿、肢体和视线方向不变。提示词只描述画面，不传入桌面或容器等产品实现概念。**短动作只使用 Grok 1.5**：动作关键帧同时作为首帧与末帧，冻结角色图另作身份参考，按各动作时长提交 720p 视频。MiniMax 不参加该路径的回退；聊天视频仍使用其原有供应商链。Grok 首尾帧 / 参考图模式的分辨率上限与请求映射见 [适配器](../backend/services/infrastructure/llm/providers/grok/video.py)。
4. 下载原始素材，语义抠像，检查可见性、透明背景和首尾接点，按动作时长上限选取至少一秒的循环片段；一秒待机支持恰好 24 帧的素材，不要求额外端点帧。不按时间或运动量猜测、拆分不同动作，也不靠倒放伪造步态。
5. 统一画布与帧率，编码透明 VP9/WebM（无音轨）；从最终编码文件提取封面和命中遮罩，校验后发布不可变版本。四个必需动作全部成功才可激活；新包失败保留旧形象。

当前供应商接口没有已实现的原生 alpha 视频输出能力，真实 Grok 输出为不透明 MP4，不能靠提示词中的“透明背景”替代抠像。导入已有透明素材时保留原生 alpha。

### 2.2 透明化、循环与消费

[matting](../backend/services/infrastructure/video_processing/matting.py) 使用 ISNet 通用前景模型保护浅色皮肤、衣物及毛发，不采用全局色键。模型由管理员放置于 `data_dir/models/<matting_model>.onnx`，缺失时在付费生成前拒绝。静止且遮罩变化较小的区域做有限时域混合，移动边缘不用历史遮罩拖尾；均匀背景下仅对语义边缘去混色，实体内部颜色保持不变。中间产物使用 FFV1/BGRA。

[quality](../backend/services/infrastructure/video_processing/quality.py) 检查逐帧覆盖率、边界残留及首尾前景颜色、轮廓和速度差异；不合格动作保留源视频并单独报告失败，不自动重复付费生成。数值门槛只能拒绝明显缺陷，不能证明动作语义、身份、细发丝或所有循环的主观质量。

WebM 的 alpha 存于 Matroska 辅助数据；读取时必须显式使用 `libvpx-vp9`（VP8 使用 `libvpx`），默认原生解码器可能丢弃 alpha。交付同时检查辅助数据和实际解码的透明 / 实体像素，不以容器标签为验收依据。上传路径支持可解码 alpha 的 WebM、FFV1/MKV、ProRes 4444/MOV 等素材；透明文件仍需存在真实前景与背景。

描述符契约见 [manifest](../backend/services/application/generation/video/manifest.py)：只携带不可变资源路径与哈希、画布、动作映射、逐帧 alpha 命中遮罩及必填采样帧率等调度信息。客户端双播放器始终挂载，备用片段开始播放且收到真实视频帧回调后才切换，短暂淡入淡出；解码、播放和首帧等待均可取消且受超时限制，失败保留可用片段，初始播放失败进入渲染降级。命中按实际播放器时间采样，并扣除 `object-contain` 留白。移动与拖拽由容器位移表达，不驱动嘴部或视线。

### 2.3 版本、恢复与删除

一个动作对应一条任务，独立保存阶段、脚本、关键帧、供应商句柄、源视频与处理结果。成功动作可预览；重做单动作创建新包版本并共享其余动作与冻结参考。共享文件在最后一个包引用消失后才回收，删除旧版本不能损坏新版本。

视频提交先保存阶段，成功取得任务 ID 后立即落库。重启后已有句柄按提交时模型续轮询、已有姿态图续提交、已有视频续处理、已成功动作直接复用；全部动作成功后发布失败可单独重试发布。视频提交中但无句柄，或姿态生成中但无产物，均视为结果未知，不自动重发。图像编辑为同步接口，没有可查询的异步句柄。继续处理前检查参考仍有效，不重做已成功动作；明确重做动作才重新请求生成。上传源只存在临时工作区，处理中断后须重新上传。

同一用户只允许一个构建中的包。发布与激活在用户锁内完成，参考图改变时拒绝迟到结果；构建期间用户切换到另一套外观时只发布，不抢回穿着。启用包时同步启用对应着装。动作包状态及恢复入口见 [PROTOCOL](PROTOCOL.md#110-视频动作包方法)。

## 3. 渲染与传输

桌面消费视频动作包 manifest 与透明片段。签名轮换不代表内容变化，资产访问、缓存和恢复遵循 [PROTOCOL](PROTOCOL.md#15-资产-url-签名与传输缓存)。显示降级顺序只在 [DESIGN](DESIGN.md#12-形象降级与兜底体系永不空白) 定义。

## 4. 按改动选择验证

参考与提示词变更检查身份、穿着、输入顺序及派生失效；编辑与自备图变更检查前置守卫和采纳后的状态一致性。视频处理变更检查真实透明片段（编码、切分、遮罩），不能仅凭能力声明通过验收；抠像与循环策略变更须检查浅色主体、透明背景、坏接点和真实供应商样本；交付产物还须检查 Chromium 实际透明合成。

恢复变更覆盖提交未落库、轮询中断、下载失败、未知结果及迟到结果。可加载性、视觉质量、模拟结果和真实供应商结果分别报告。

仅修改文档时核对事实与链接，不要求重新触发付费生成。验证入口见 [Scripts](../scripts/README.md)。
