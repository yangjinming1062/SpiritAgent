# 形象生成能力链

本文维护参考来源、形象能力编排、产物和失败恢复。

## 1. 参考与派生关系

```text
角色定义 + 已确认头像
          ↓
    独立全身种子图
      ├─ 外观参考正面立绘 → 确认锁定身份 → 外观（着装参考）设计
      ├─ 模型正面种子 → 可选背面种子 → 生模 → 可选绑骨 → 可选动画
      └─ 房间、自拍与其他出镜媒体
```

### 1.1 共用参考与种子图派生

| 输入或产物 | 必须保持的语义 |
|---|---|
| 头像 | 锚定身份；关系定位只影响交流，不作为外貌属性 |
| 独立全身种子图 | 由头像与角色定义补全身材比例；姿态自然，不直接提交生模 |
| 外观参考正面立绘 | 从全身种子图派生，固定动漫插画画风（`anime_illustration`）、自然站姿；确认后锁定身份，并作为外观设计的身份参考 |
| 模型正面种子 | 从全身种子图独立派生；双足使用 A-pose，画风按物种路由（类人精绘 / 非人写实）；不覆盖外观参考 |
| 模型背面种子 | 与正面配对；重绘模型正面使旧背面失效；背面失败可退回单正面提交 |
| 换装草稿 | 全量重绘始终以独立全身种子图锚定身份与身材，不反复引用旧外观造成漂移 |

非双足姿态按骨架采用自然站立或舒展，不机械套用 A-pose。画风与姿态分别决定；提示词只写宽高比，像素尺寸由请求与供应商实现决定。

带图提示词按输入用途表达任务：头像补全全身、原图角色调整视角或姿态、换装、进入场景、局部编辑分别明确允许改变的内容，保留原图已确定的角色特征。内部生成与自备图共用派生模板；外观参考与模型种子按链路调整画风，背面按正面结构补全，不镜像正面。上传头像附带风格参考时，主体图确定角色，风格图只提供呈现方式；双图经左右拼图传输，提示词按图 1 / 图 2 说明分工。

用户服装参考图先与文字整合为着装描述，不直接作为换装生图的身份参考；整合失败可按纯文字生成。房间和出镜媒体必须取得可读的全身种子图，缺失时停止并提示修复。

房间以全身种子图确定身份和身材，以当前着装描述确定穿着；用户场景图只提供布置、氛围、构图及明确要求的姿势，不引入额外人物或改变身份。文字要求优先于场景参考，场景参考优先于默认布置。

普通对话的 `subject='self'` 图片使用独立全身种子图作身份参考，视频以该图为首帧。夜间出镜图片另按可用性带入当前外观参考；夜间出镜视频仍使用全身种子图并保留图中穿着，不能用于承诺展示刚换上的衣服。夜间媒体的 `narration` 生成独立音轨，不保证视频口型同步。

全身种子图重绘成功后才替换旧图，不自动重建既有外观、模型或房间资产。换装后的房间着装一致性另按 [PROTOCOL](PROTOCOL.md#12-伙伴生命周期方法方法级契约) 处理。

### 1.1.1 图像修改双模式（微调 / 重新生成）

`mode` 缺省为 `regenerate`，按各点位固定参考全量重绘。`edit` 使用上一版产物作为编辑底图，只改变反馈指定部分，必须同时满足：反馈非空、旧图存在且可读、未附加参考图、供应商声明并实现图像编辑能力。

编辑条件不满足时明确失败，不能静默改成全量重绘。身份条件化参考不等同于图像编辑能力；具体能力位与路由见生成模块。

### 1.1.2 用户自备图

用户获取完整提示词，并用客户端本地缓存的种子参考图在外部工具生成后上传采纳。提示词以参考图锚定身份；各点位参考图与 AI 生图同源：全身参考用头像种子，外观参考 / 换装 / 房间用全身种子，背面用模型正面种子。提示词不引用产品内部概念或供应商专有参数；采纳进入与正常生成相同的确认、存储、事件和激活流程。外观参考与换装点位提示词固定为动漫插画画风，与形象参考链保持一致。

对应参考图在 onboarding 后恒在：提示词与 AI 路径都必须带参考图，缺失或不可读时同样明确失败。外观一致性由用户确认，不宣称程序完成身份验证；自备图不区分微调与重新生成。

外观确认接口不携带图片载荷：确认把草稿立绘转正为持久参考图（`ready`），只表示参考图就绪，不触发任何生成，也不自动穿着；穿着经激活接口显式完成。设计草稿阶段即可获取自备图提示词。

房间获取提示词时创建 `source=user_upload` 的 pending 行，不启动 AI 生成，也不被生成恢复程序误启动；采纳进入 ready，放弃进入 superseded。

### 1.2 模型阶段与持久化

各阶段通过供应商任务 ID 串联，最终 GLB 下载落盘。缺少绑骨能力或绑骨失败时可交付基础模型；只有绑骨成功、支持动画绑定且动作集合非空时才进入动画阶段。

动作映射只在动画绑定实际成功后持久化。空映射表示不承诺动画，不能用声明的能力代替真实产物。

## 2. 能力声明

[CharacterModelProvider](../backend/services/infrastructure/model_generation/base.py) 定义生模、轮询、下载和可选能力。多视角、绑骨、动画及负面提示词能力必须与实现一致；不支持多视角时只提交正面图。

供应商 token、骨架命名和请求参数留在适配器，客户端只消费统一资产与语义动作映射。不为缩短接入流程而把供应商命名复制到渲染端。

## 3. 失败与重试语义

| 状态 | 处理 |
|---|---|
| 未配置供应商 | 提示配置，不进入生成 |
| 有任务 ID，供应商已成功 | 恢复后续阶段或下载，不重做已确认阶段 |
| 有任务 ID，仍排队、网络异常或结果未知 | 保留任务并核对，不盲目重新提交 |
| 供应商明确终态失败 | 可由用户重新生成；是否再次计费由供应商决定 |
| 下载失败且已有可恢复任务 | 提供“重试下载”，不替换成“重新生成” |
| 缺少可恢复任务句柄 | 不能宣称能接续既有付费任务；按失败状态向用户提供处理入口 |

生模句柄在提交后、轮询前保存；绑骨和动画句柄当前在各阶段成功后才更新。提交至保存之间仍有崩溃窗口，恢复可能重复提交某一跳。供应商任务和下载地址也有外部保留期，因此不能承诺绝不重复计费或永久可恢复。

新生成使用独立记录，就绪后形成唯一激活模型；当前实现发起新生成时会解除旧记录激活态。客户端保留已有可用呈现的体验要求，不等于数据库始终保持旧模型激活。非强制请求可复用有效模型，避免无意重复生成。

## 4. 模型产物契约（Tripo3D `spec=tripo`）

当前 Tripo 链使用 `spec=tripo`。骨骼命名规范与绑骨算法版本分别配置；改变其中任一项，都须检查绑骨、动画绑定及客户端引用，不能只验证生模成功。

实际预设与骨架映射见 [Tripo 适配器](../backend/services/infrastructure/model_generation/providers/tripo/client.py)。未绑定动画的骨架允许空动作映射；蒙皮辅助骨不直接作为动画目标，缺少面部骨骼不能被描述为支持完整面部动画。

## 5. 模型客户端消费

`animation_clips(rig_type)` 定义语义键与供应商动作名称的映射；成功结果保存于 `clip_map_json`，随查询响应和 `model.ready` 交付。

客户端依次尝试候选全名精确匹配、去命名空间后的叶名精确匹配、叶名子串匹配。语义键缺失时先尝试 `idle` 映射；已有候选但匹配失败时不再额外尝试 `idle`。最终无匹配则保持绑定姿势，不报动画成功。

模型只接收可请求的语义动作，状态和交互专用动作不开放给自主推理。具体映射见 [AnimationMap](../client/renderer/modules/character/rendering/model/AnimationMap.ts)。

## 6. 视频动作包链

两条创建入口共用交付链（切分与时间轴归零 → 统一画布与脚底锚点 → 透明 VP9 编码（WebM、无音轨）→ 封面与命中遮罩 → manifest 校验 → 不可变包发布）：

- **按参考生成（默认入口）**：LLM 演绎脚本 → 参考图 i2v 生成单条长视频 → 服务端抠像与动作分割 → 逐段切分编码 → 发布后自动激活。视频链固定写实渲染（photorealistic）：提示词骨架要求真实皮肤/毛发/布料质感与自然光影，不呈现为动漫、插画或卡通渲染（与外观参考立绘的固定动漫画风无关，见 [prompts/generation](../backend/prompts/generation.py)）。脚本模板固定动作集合与顺序（`idle / walk_left / walk_right / drag`）、循环性与节奏提示；每个动作「怎么动」的 motion_prompt 由模型结合角色性格、物种与说话风格动态撰写（脚本快照存 `companion_video_jobs.script_json`）。视频提示词骨架固定单镜头、全身入画、纯色浅背景、动作间约 0.4s 空白间隔（角色完全走出画面）与中立起止姿势；分辨率取供应商最低档、时长预算取链上各供应商最大时长的最小值。
- **上传导入**：自备已制作片段或长视频区间，发布后显式激活。源片段须为**像素级 alpha 格式**（FFV1/MKV、ProRes 4444/MOV 等）——WebM/VP9 的 alpha 走封装旁路（见下），服务端滤镜解码不到，透明标签不满足该判据的源明确失败。

- 描述符 `spiritagent.video.pack/1` 只含数据：动作键 → 不可变资源路径 + SHA-256、画布/帧率/脚底锚点、每秒采样的低分辨率 alpha 命中遮罩、调度约束（默认动作、播放倍率上限、镜像许可）。必需动作 `idle / walk_left / walk_right / drag` 齐备且校验通过才可发布；发布即版本固化，单动作重做生成新版本，禁止把不同外观版本的片段拼成同一运行包。
- 处理由服务端 [video_processing](../backend/services/infrastructure/video_processing/) 执行：FFmpeg 参数由代码构造并受超时约束，不向客户端分发 FFmpeg，不执行任意参数。
- **抠像**（[matting](../backend/services/infrastructure/video_processing/matting.py)）：低分辨率预扫从画面边缘采键色——背景近纯色时 FFmpeg `colorkey` 整段色键，实体覆盖率护栏防止角色与背景同色被穿透；否则 ISNet onnx 逐帧抠像（模型文件 `data_dir/models/<matting_model>.onnx`，槽位 `SETTINGS.matting_model`），模型缺失且背景不纯色时明确失败。中间产物为 FFV1/MKV（像素级 `yuva420p` alpha，可被滤镜无损解码）。
- **动作分割**（[segmentation](../backend/services/infrastructure/video_processing/segmentation.py)）：空白间隔优先（中间产物逐帧 alpha 覆盖率扫描，段首尾修剪出入场过渡）；段数与脚本动作数不符时进入运动能量兜底（低分辨率灰度帧间差分，物种无关——姿态识别方案因无法覆盖猫狗等非人物种而弃用）：按衔接处运动最小合并多余段、不足的段做偶分切分并吸附到运动局部极小帧。无可见角色或有效实体帧不足的片段直接拒绝；两级策略都失败才判整包失败并提示重新生成，尽量挽救已付费生成；分割不依赖脚本时间轴（视频模型对时间遵循只是近似，实测常把多次空白演绎成一次进出画）。
- **WebM/VP9 alpha 真伪**：alpha 以 Matroska BlockAdditional 封装旁路携带，FFmpeg CLI 解码不回读——内部处理（分割、命中遮罩、封面）一律在像素级 alpha 的中间产物上执行；交付验收以封装层侧数据为准（ffprobe `-show_packets` 的 `Matroska BlockAdditional`），容器 ALPHA_MODE 标签单独不构成证据。
- 状态与阶段分离逐任务持久化（`status` × `stage`：脚本 / 提交 / 生成 / 下载 / 处理 / 发布）；按参考生成的整包任务用哨兵动作 `full` 表示（一条长视频任务），供应商任务句柄在提交成功后立即落库，进程重启凭句柄续轮询（不重复提交付费任务）、处理中断凭 `artifact_path` 直接续处理，不再查询供应商；脚本已落库且尚未进入提交阶段时可续提交，提交中但无任务句柄时按结果未知失败落库，不自动重发；上传导入源在临时工作区，重启按失败落库。生成源视频持久保留（不随发布清理），供切分与抠像迭代复盘，随包删除时回收。同一用户同时只允许一个构建中的视频包；发布与激活在用户锁内翻转，迟到构建凭参考版本哈希拒绝，新包失败不清空旧激活包；生成路径发布与自动激活在同一事务提交。
- 事件 `companion.video.progress`（阶段文案）/ `ready` / `failed` / `activated` 只触发状态刷新与生成状态机更新，不写入聊天历史。
- 客户端消费透明片段循环播放，双 video 交换切换动作；命中按遮罩查表（最近采样），移动与拖拽由容器位移表达，播放不驱动嘴部或视线。

## 7. 渲染与传输

模型消费 GLB 与动作映射，视频消费动作包 manifest 与透明片段。签名轮换不代表内容变化，资产访问、缓存和恢复遵循 [PROTOCOL](PROTOCOL.md#15-资产-url-签名与传输缓存)。显示模式与降级顺序只在 [DESIGN](DESIGN.md#12-渲染模式与降级体系永不空白) 定义。

## 8. 按改动选择验证

参考与提示词变更检查身份、穿着、输入顺序及派生失效；编辑与自备图变更检查前置守卫和采纳后的状态一致性。供应商变更检查真实 GLB，视频处理变更检查真实透明片段（编码、切分、遮罩），不能仅凭能力声明通过验收；抠像与分割策略变更须分别覆盖纯色与非纯色背景、含与不含空白间隔的样本，交付产物以浏览器实际渲染的透明表现为准（FFmpeg CLI 解码不回读 WebM alpha）。

恢复变更覆盖提交未落库、轮询中断、下载失败、未知结果及迟到结果。可加载性、视觉质量、模拟结果和真实供应商结果分别报告。

仅修改文档时核对事实与链接，不要求重新触发付费生成。验证入口见 [Scripts](../scripts/README.md)。
