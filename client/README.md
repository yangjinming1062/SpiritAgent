# Client

## 1. 职责与边界

负责桌面呈现、凭据、协议中转、Runner 生命周期和更新。推理归 Backend，本机工具归 Runner。

内部修改进入 [主进程](main/README.md) 或 [渲染层](renderer/README.md)；本文只定义两者及各窗口之间的协作。

## 2. 设计意图

凭据与本机能力集中在可信主进程，渲染层经受控桥调用；各窗口复用一条网关连接，但分别维护显示状态。已有缓存可加速呈现，不能取代后端真源或掩盖错误。

## 3. 架构地图

`main` 管身份、窗口和 Runner；`renderer` 管交互与呈现；`shared/ipc` 定义跨进程通道和载荷。渲染侧 `renderer/shared` 不是主进程共享库，不允许主进程导入依赖窗口环境的实现。

主进程与 preload 由 tsup 构建，渲染层由 Vite 构建。preload 格式、安全和产物路径约束见 [主进程](main/README.md#包边界)。

## 4. 跨进程协作

### 连接与设备就绪

桌面精灵宿主持唯一 WS 并负责 Runner 派发，其他窗口通过主进程代理；每个窗口独立水合并读取斜杠目录。不能多窗各自连接，也不能把相同模块误认为共享内存。

Runner 断开、退出或停止时立即作废能力缓存，网关仍连接则同步空工具表。新握手先推配置再读工具，旧查询与旧同步结果不得恢复已撤销资格。当前运行期能力通知和 `run_generation` 尚未完整接入就绪聚合，详见 [PROTOCOL](../docs/PROTOCOL.md#23-runner_ready-capabilities-与-health-状态)。

普通会话切换不重置实时事件水位；调用恢复使用原 `call_id`，不能因响应丢失生成新标识重做操作。

### 窗口与主题

主进程串行裁决生活空间与工作台互斥，记录上次入口；工作台与伴工精灵是一个物理窗口。开关窗口只改变呈现，不取消已执行工具。

主题在 `loadURL` 前从配置镜像写入入口参数，渲染模块加载时优先消费并移除参数；localStorage 是即时缓存，云端水合负责收敛。镜像异常回退默认主题，不阻塞开窗。

透明窗口和首帧 body 必须同时透明；圆角与阴影由 CSS 绘制，不用系统矩形底填满外侧透明区。鼠标穿透是窗口级能力，精灵与弹层共同登记命中区域，不能让弹层捕获整个桌面。

精灵窗只覆盖当前显示器工作区，跨屏统一换算原点与坐标，避免二次平移；恢复先选屏再定位，拔屏回到可用显示器。跨窗口附件通过主进程信箱转交，不只写来源窗口 store。

### 资产与历史缓存

主进程缓存资产字节；外观页另缓存外观列表并顺序预取。缓存按内容哈希、包版本或不可变资源路径复用，签名变化不代表内容变化。旧字节可先呈现，新资产就绪后替换；网络失败保留旧形象，鉴权失败进入会话过期流程。

语音条首次播放时下载到主进程磁盘缓存，后续播放及重启后优先本地读取，同一音频的并发下载合并。尚未播放的语音不预下载。

图片、语音与视频等本地资产缓存不设置文件数量或字节总量淘汰，直接交互 TTS 的磁盘缓存同样持续保留。会话资产在登出、换号或显式清理时删除；损坏文件可移除并重新获取，存储空间不足时报告写入失败，不自动删除其他有效资产。

历史按用户和会话缓存快照。打开会话先显示快照，再以末条消息 ID 请求增量，锚点失效则全量恢复；IM 始终全量更新 queued 状态。快照不记录实时回合，不能用其旧 seq 请求帧重放；`last_seq` 只用于重连时仍保有活数据的列表。

语音音频更新会修改已有消息，不能仅靠末条 ID 增量获取。收到更新后保留当前历史作为展示基底、废弃磁盘快照，并强制下次同步取全量；更新与在途请求交错时重新读取，连续变化超过重试预算则保留当前界面并报告同步失败。重复完成事件中的空音频不能覆盖已经就绪的音频。

编辑、撤回、压缩与清空覆盖对应历史快照，删除会话同步删缓存。登出或换号清理所属资产与历史，迟到下载、装配和写盘不能恢复旧用户数据。

依赖准备见[源码启动](../README.md#从源码启动)，命令见 [Scripts](../scripts/README.md#8-按改动选择验证)。IPC 变化同时核对共享类型、preload、主进程处理器和调用方；异步变化覆盖切换、断连、登出及迟到结果。透明合成、多屏、快捷键和 GPU 恢复须在相应平台验证。
