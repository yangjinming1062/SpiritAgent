# Windows 桌面宿主

原生宿主、恢复与构建的工程入口，Electron 生命周期归主进程 README。命令和载荷在 [main.rs](src/main.rs)，接管及恢复在 [windows.rs](src/windows.rs)，运行窗口在 [applications.rs](src/windows/applications.rs)，工作区在 [workspace.rs](src/windows/workspace.rs)。

| 模式 | 职责 |
|---|---|
| `host` | 从 stdin 接收受限 JSON，使用主进程登记的 HWND 接管桌面 |
| `guardian` | 独立监测主进程、host 与十秒续租，异常或 Ctrl+Alt+Shift+D 时恢复 |
| `recover` | 处理待恢复 journal |
| `check-runtime` | 验证可执行文件可加载，无桌面接管副作用 |
| `allow-foreground` | 核验前台父进程与同源 host 身份，转授一次外部前台请求的 Windows 权限，不接管桌面 |
| `display-bounds` | 按 Electron 转换后的显示器矩形只读查询原生像素尺寸，不访问 Explorer、journal 或桌面接管 |
| `tray-probe` | 按 Explorer 任务栏 HWND 只读查询 UI Automation 托盘边界；host 在独立子进程内限制查询耗时 |

## 挂载与输入

宿主分别识别 `SHELLDLL_DefView` 图标层与壁纸承载层，使视频位于原生图标下方、系统壁纸上方。分层图标结构必须先确认同父层下已分离出可见的壁纸 WorkerW，再将分层视频窗口排在图标与壁纸之间；仅有分层样式时，图标视图仍可能绘制不透明的系统壁纸。传统结构使用图标层后方的 WorkerW；两种结构缺少壁纸层时均在 guardian 就绪后有界请求 Explorer 创建并重新识别，巡检同时验证壁纸层身份与顺序。不能只按 Windows 版本选择层级，也不能通过隐藏共享图标层或修改图标偏好实现接管。界面保持普通顶层；接管只接受同一显示器的一份背景与一份界面。

附着前核对父进程、窗口身份和完整 DPI context。请求须对应完整显示器，四项物理几何误差均不超过两像素；附着后复验外框和客户区。Electron 关闭 `frame`、`thickFrame`，helper 去掉非客户区并按实际 Explorer 结构设置背景样式。样式、父层、几何和置顶信息在变更前进 journal。视频不接收鼠标输入，透明界面只命中已登记交互区域，其余区域交给 Explorer；挂载与巡检验证图标在视频上方，不能再以视频获得桌面输入作为成功依据。

`display-bounds` 接受一组近似物理矩形，设置自身 PMv2 context 后复用上述匹配规则，通过 `GetMonitorInfoW` 返回真实矩形；无法匹配的项返回空值。Electron 的 DIP 宽高已取整，乘缩放因子或再次转换都可能偏差一至两像素，不能据此记录桌景分辨率。该查询独立于桌面模式，在启动及显示器变更时刷新，缓存绑定显示器 ID 和当前几何。

`focus` 仅接受身份、父层和可见性匹配的登记窗口，且系统须处于桌面前台。界面即使已有焦点仍先置前；修饰键与鼠标释放后临时附着输入线程，完成复验焦点和实际前台。线程解除失败退出 host，交 guardian 恢复。桌面前台只认可挂载层及自有窗口家族。

## 运行窗口

枚举当前虚拟桌面各屏普通与最小化窗口，附带交互屏归属，排除系统壳、工具浮窗、隐藏和产品窗口。会话共用 WinEvent，命令及轮询前处理消息，合并相邻重复事件但保留移动、销毁顺序；位置与跨屏移动后更新归属，每两秒补扫，队列溢出清登记后全量校准，COM 与监听随会话释放。

helper 通过 `get_jump_list_tasks` 只读解析用户 Jump List 的 `Task` 分类，通过 `activate_jump_list_task` 重新读取并校验任务 ID、目标程序和桌面会话后启动。解析仅接受有界的 Shell Link 数据，支持 exe 与 `shell:AppsFolder` AUMID 任务；无法识别的链接跳过，仅因 `--user-data-dir` 不同的同一任务合并。损坏文件跳过并记录诊断，不把程序参数交给渲染层，任务解析诊断不打断现有菜单。

未变化不广播；快照按 revision 分批，每行最多 64 KiB，主进程收齐才应用，换代丢弃未完成批次。总量和等待预算归 [explorer-desktop-host.ts](../main/lifecycle/explorer-desktop-host.ts)。

- `activate_external` 复核会话 ID、窗口身份、虚拟桌面和前台；固定项与目录入口的异屏回退允许跨屏迁移，其余请求要求窗口仍在交互屏。命令回执表示激活已登记。状态机区分本屏激活与跨屏迁移：本屏仅在最小化时还原，保留原尺寸、最大化和全屏布局；跨屏保留最大化状态并按 DPI 适配工作区，已显示的最大化窗口同时迁移当前外框和还原位置。根窗口准备后再解析与准备当前模态目标，迁移完成须确认原生回执和外框完整进入目标工作区，必要时至多校正一次。
- 目标就绪且取得执行名额后才请求前台授权。主进程沿用原始输入与账户资格，由短命子进程核验当前前台并转授 Windows 权限；排队请求另保留失焦历史，已受理请求允许穿过前台暂空。每轮授权绑定原生操作 ID、单调代次和当前模态目标。授权回执及工作线程执行前均复验前台、窗口身份和屏幕；模态分支或几何变化重新规划并换新授权，不能复用旧权限。前台为空表示暂缓，真实切到其他程序表示正常取消，实际调用失败结束请求并诊断。外部程序输入队列保持隔离，主循环确认实际前台。
- `close_external` 整批核验交互屏归属后逐个投递 `WM_CLOSE`，有未决模态对话框则拒绝整批，投递前再次核验；回执不代表窗口已关闭。
- 隐藏 owner 下多个主窗保持分支隔离，不能用 `GA_ROOTOWNER` 代替用户所选窗口；禁用主窗只查找该分支可交互弹窗。

`launch_external` 与 Jump List 共用原生启动定位。文件及快捷方式通过带目标显示器的 Shell 启动，打包应用通过激活接口取得进程身份；工作线程承担启动等待，host 心跳不阻塞。定位监听与会话同生命周期，15 秒内关联启动前窗口集合、进程身份及新增窗口。单实例启动复用旧窗口时，须无后续输入、同程序仅有一个窗口且前台从其他分支切入，并由返回的既有进程身份或已退出的启动进程证明交接。已关联窗口复用激活迁移机制，一次成功即消费；关联歧义或到期报告未能定位，原生调用失败保留实际原因，不能持续吸附同程序窗口。

窗口迁移、普通工作区约束与前台请求由受管理的 PMv2 工作线程执行同步原生调用，完成回执只证明该次调用返回，主循环还须核对身份、屏幕、DPI、最大化状态及实际外框。尚未返回或外框尚未满足目标时保留待确认，不以总耗时或几何静止时长推断拒绝。等待外部程序期间不持恢复锁，host 继续处理心跳与停止。

同一 HWND 的原生调用单飞，工作线程与焦点预留合计最多 16 个；已取消但仍阻塞的线程继续占用名额，返回后回收，不重复创建线程规避限制。名额暂满保留迁移或去重后的工作区约束意图，释放后按新鲜几何重试，不归为拒绝；授权前预留名额，避免取得权限后再竞争。已回执但实际位置尚未满足的只读观察不占线程配额，可由该窗口的新请求替换。用户新的按键、点击、滚动或转去其他前台窗口，以及拖动、窗口失效、工作区变化和会话结束，都会取消后续校正与焦点步骤；鼠标悬停、原始手势释放和 Windows 暂时没有前台窗口不视为新操作。取消不承诺撤回已进入 Windows 的调用。正常停止先取消任务再恢复系统，不等待阻塞线程，存活线程随 host 退出结束。

## 原生系统托盘

探测与刷新归 [tray.rs](src/windows/tray.rs)，任务栏位置恢复归 [tray_placement.rs](src/windows/tray_placement.rs)，窗口区域及恢复快照归 [regions.rs](src/windows/regions.rs)。

接管交互屏原有任务栏，将其平移至 Dock 中的托盘槽位，保持任务栏尺寸、父子关系和原生托盘子树，仅显示托盘与滚动视口的交集。优先读取 `TrayNotifyWnd` 的真实边界；缺少该窗口时，通过只读 UI Automation 定位本屏托盘与时钟，并核验任务栏身份、Explorer 进程、显示器和坐标。查询设时限，不阻塞 host 心跳与恢复；无法可靠定位、移动或应用区域时结束接管并恢复窗口模式。

只集成交互屏原有的系统托盘，不跨屏复制完整托盘，不把第三方任务栏面板算入托盘，不使用固定像素宽度。托盘固有尺寸与平移后位置分离，滚动不触发尺寸反馈；WinEvent 与周期巡检刷新图标增减、显隐、DPI、布局和 Explorer 重启后的边界。槽位变化先发布会话内的物理目标，再更新原生位置与裁剪；托盘保持在 Electron 玻璃背景上方接收输入。原生图标回调、隐藏图标菜单、提示和系统面板继续由 Explorer 处理，弹窗不参与任务栏裁剪或普通窗口工作区校正。

Explorer 激活任务栏时会请求回到屏幕边缘，不能仅靠事后巡检拉回 Dock。样式模块在登记任务栏所属线程安装可逆窗口子类，在 `WM_WINDOWPOSCHANGING` 原处理返回后约束位置，保留尺寸、层序和其他窗口标志，不代理原生输入。目标使用独立映射与有界 seqlock 读取，绑定原样式会话的宿主创建身份、任务栏和续租；样式与位置约束均确认就绪才显示原生行。空布局或全屏先暂停位置约束，停止与失租使其透传并在所属线程解除；`SWP_NOSENDCHANGING` 等不经过该消息的变动仍由有界校准与失败恢复兜底。

透明样式由 [tray-style](tray-style/tray-style.cpp) 的 SDK-only C++/WinRT 模块在 Explorer 内应用：清除登记任务栏的 XAML 背景填充与边线，系统前景按主进程传入的应用明暗主题切换；第三方通知位图保持 `Image.Source`，仅在所属图像网格添加居中 24 DIP、四角均为 6 DIP 的浅色半透明底片，保证深色背景下可辨认。依赖属性只在目标值变化时写入，并记录原值以供恢复；XAML 树变化不重复刷写现有样式，系统面板与其他任务栏不参与改样。窗口合成透明与 XAML 透明均须确认成功，结构不支持或状态失效时恢复窗口模式。

样式会话使用受限命名共享状态，核对同一 Windows 会话、host 创建身份、Explorer 与任务栏身份，并在有界续租失效、host 退出或正常停用后由 Explorer 内模块恢复原始依赖属性。原值保留在所属 XAML 线程，恢复后解除属性观察；任务栏重建重新识别，不能把旧对象或旧窗口的原值写入新对象。进程内诊断订阅单飞并在成功后复用，初始化失败允许后续会话重试，迟到错误只归属发起会话。样式模块以内容 hash 命名，启用前按实际 DLL 字节另存到当前用户 `LocalAppData/SpiritAgent/native/tray-style/` 的独立不可变目录，逐字节核对缓存后才加载，避免 Explorer 长期映射安装或开发目录中的文件而阻塞更新。已缓存或载入 Explorer 的 DLL 不覆盖或删除；下次启用按 manifest 选择当前模块。

透明界面保留完整 Dock 玻璃绘制，原生托盘位于其上方，界面不代理图标点击或重新实现系统面板。helper 接收经主进程验证的物理槽位与裁剪视口，未收到布局、布局清空或桌面界面隐藏时收起托盘；上报固有尺寸与实际可见性，由主进程换算为界面投影。外观与布局归 [DESIGN](../../docs/DESIGN.md#桌面模式)，状态边界归[呈现契约](../../docs/PROTOCOL.md#桌面呈现与本机启动器)。

## 工作区与层级

Shell AppBar 仅注册交互屏底部预留，协商位置时计入系统已有占用；保留托盘不重复扣除任务栏高度，不新增顶部预留，也不因打开菜单、轻语或功能窗口扩大预留。尺寸由 Client 的共享布局传入，helper 以原生像素协商并上报实际工作区，供原生窗口定位和内部界面布局使用。注册、位置变化处理、延迟启动定位与 guardian 恢复共用锁；probe 不注册 AppBar 或调整外部程序。共享 Explorer 前台按指针所在屏幕判定，其他屏桌面操作不取得交互屏焦点资格。

WinEvent 合并显隐、前台、位置、还原和移动缩放后校正普通窗口：先平移，过大再缩小，不激活窗口；系统菜单、输入法候选、隐藏、最小化和真正全屏不调整。全屏判断排除 Explorer 桌面、WorkerW 及系统弹窗宿主；隐藏图标或快捷设置的透明宿主即使覆盖全屏，也不能触发界面收起与任务栏复位。真正全屏期间收起界面，退出恢复，回系统桌面不收起界面。

`showInactive()` 可能让 Windows 收窗进工作区，须按实际原生矩形异步复验，不能信 Electron 缓存。几何和显隐校正用 `SWP_NOZORDER` 保层级；图标与视频的原生层级或两像素容差几何持续两秒不收敛则诊断并恢复。Explorer 重启后重新识别承载层与 AppBar 注册，恢复失败退回窗口模式。全屏、最小化及退出顶层承载清复验计时。

## 恢复

guardian 持恢复原值并成功注册紧急键后才接管。恢复信号绑定会话及 host 创建身份，在恢复锁内置位后拒绝新的接管写入；信号写入失败只停止核验通过的自有 host，诊断失败仍优先恢复。

journal 必须包含明确的接管阶段，仅未开始挂载的记录可直接清理。AppBar 窗口身份、背景样式、任务栏原始屏幕归属、DPI 与几何、置顶状态，以及任务栏裁剪前的区域与必要显隐状态都在变更前保存；透明界面的区域保持原样。每次恢复先复核窗口身份，不能将旧几何或区域写入复用的 HWND。正常停止和 guardian 恢复先禁用原生位置约束与透明样式，再注销 AppBar 释放工作区预留，还原任务栏几何、置顶、窗口区域与系统界面；原屏幕或 DPI 已变化时由 Explorer 重新协商位置与尺寸，避免写回旧缩放下的任务栏高度。原样式映射保持既有格式，派生位置映射缺失时仍可恢复遗留 journal；辅助映射出错也继续尽力恢复可核验的原样式会话，并保留错误与 journal。不保存或回写桌面图标坐标，保留用户使用期间的整理结果。异常写 `.interrupted`、正常停止不写；恢复信号按会话隔离，host 不覆盖 guardian 原因。诊断有界写 `.guardian.log` 和 stderr，失败保留 journal、guardian 重试；所有恢复进程均被强杀时由下次启动处理待恢复记录。

挂载摘除后仅重绘释放屏幕的 Explorer 区域，不重设系统壁纸；恢复失败保留 journal 继续重试。

## 构建

构建需 Rust 1.85 以上、Visual Studio 2022 以上的目标架构 C++ 工具及含 C++/WinRT 的 Windows SDK；Windows 开发和打包自动准备 helper 与托盘样式模块，终端用户不需工具链。手动入口：

```sh
pnpm --dir client build:native
```

[build-desktop-host.cjs](../scripts/build-desktop-host.cjs) 按 Electron 架构生成 `client/build/<arch>/desktop-host.exe`，并调用[样式构建](../scripts/build-desktop-tray-style.cjs)生成同目录下的内容 hash DLL 与 `desktop-tray-style.json`。样式 hash 覆盖架构、源码和构建输入；复用前核对 manifest、预期文件、架构及普通／延迟导入，不接受额外 VC／UCRT 依赖。样式采用 `/MT`，无需新增第三方库；开发输出保留旧 hash DLL，独立打包暂存只包含当前 manifest 及选定 DLL，随 helper 放入 `resources/`。打包后再次校验架构与静态运行库。`cargo check --locked` 不验证 C++ 模块、链接或打包。

开发 launcher 使用独立 Electron 副本，开发和 Windows 打包均写 `PerMonitorV2, PerMonitor` manifest，保留其他元数据；helper／DPI 准备失败阻止桌面模式，恢复入口仍可调用已有 helper 处理待恢复记录。补齐工具链后须重启客户端。主进程及两种 preload 重编译先正常恢复桌面再重启；取消开发亦先等 Electron 退出，60 秒超时仅停自有主进程，由 guardian 恢复。

### 安全运行检查

`check-runtime` 只输出 `runtime_ready` 并以 0 退出，不设置 DPI、访问 Explorer、读写 journal 或注册热键。

## 原生验收

`SPIRITAGENT_DESKTOP_PROBE=1` 会挂载背景但保留系统任务栏，不预留工作区；系统图标沿用原有显示偏好。加载检查和挂载探测均不代替 [Windows 原生验收](../../scripts/README.md#windows-桌面验收)。
