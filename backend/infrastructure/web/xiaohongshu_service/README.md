# 小红书账户采集服务

在固定上游版本上提供账户隔离的采集与扫码接口，复用官方镜像的浏览器。上游提交、校验和与补丁入口以 [Dockerfile](Dockerfile) 为准；[login_admin.go](login_admin.go) 实现隔离接口，[upstream.patch](upstream.patch) 调整上游注册与浏览器，Backend 经 [xiaohongshu.py](../xiaohongshu.py) 调用。

## 构建与运行

Go 模块签名校验保持启用。`backend/.env` 的 `XHS_BUILD_GOPROXY`、`XHS_BUILD_GOSUMDB` 可覆盖构建源，直接构建使用 `GOPROXY`、`GOSUMDB` 参数；默认值留在 Dockerfile。逗号分隔的 Go 代理只在 HTTP 404/410 时回退，网络超时仍失败。`XHS_PROXY` 仅控制运行时浏览器出站。

默认 Compose 通过内部网络提供服务，不设访问令牌、不映射宿主机端口；原全局 REST/MCP 入口不注册。平台 Cookie 每次由 Backend 传入，不读全局登录文件或共用 profile，无需凭证数据卷。部署命令和账户配置见 [Backend](../../../README.md#免费社交资讯来源)。

`XHS_MAX_BROWSERS` 限制扫码和采集的总并发，等待扫码也占名额；满额立即返回 503，不排队。每个浏览器使用独立临时目录，在成功、失败、取消或超时后关闭并清理。全部账户接口设 `Cache-Control: no-store`，日志不记录正文和平台原始错误。

## 扫码会话与凭证交接

内存会话由随机 `owner` 和 `session_id` 共同定位；新建二维码仅替换同一 owner 的会话，Backend 再校验所属账户和登录修订。浏览器生命周期归扫码会话，不随二维码请求或客户端页面关闭而结束。

查询和短信验证复用同一页面。验证码仅接受六位 ASCII 数字，只向可见验证弹窗的唯一输入框提交一次；有界等待后保留明确状态，不自动重填、重发或重复确认。有效期、等待上限和错误分类以 `login_admin.go` 为准。

扫码成功关闭浏览器，结果携带当前平台 Cookie 供 Backend 条件保存；结果可重复读取，保存成功后由取消接口确认清理，未确认结果到期销毁。取消、替换和到期均清空 Cookie，重启丢失会话后须重新扫码。找不到或归属不符返回 409，已过期返回 410，不回显请求信息。

## 采集与验证

搜索固定使用最新、一天内筛选；详情仅读取目标笔记，不加载全部评论。Backend 每次接口调用前重查账户政策、凭证修订与预算，保存前校验来源、正文和实际发布时间。浏览器内部资源不计作 Backend 接口次数，健康检查不能证明平台已登录或取到了有效内容。

构建时先校验归档与补丁可应用性。实际验收覆盖并发扫码、替换/取消、短信一次提交、满额、重启与 Cookie 交接，并使用有效个人登录检查搜索和详情；模拟响应不能证明平台兼容性。
