# 对话编排

桌面、手机、Cron、主动陪伴和子 Agent 共用的回合执行层，负责上下文、模型调用、工具派发及回复交付。本页维护内部装配、历史边界与任务所有权。

## 受理与所有权

HTTP 受理由账户任务持有，调用方取消不能中断已持久受理。结构与输入互斥由 [http_contracts.py](../../features/conversation/http_contracts.py) 校验，工作流核对附件、额度和消息资格；[会话提交账本](../../features/conversation/submissions.py) 在锁内原子保存完整消息序列、附件和请求，重复提交复用原结果。传入 `persisted_message_id` 时输入已由调用方保存并发布，编排不再插入或通知。

`run_chat_turn` 的会话锁覆盖回合及取消收尾；回合起点（`_load_turn_setup`）核对身份与输入，上下文装配（`_prepare_turn`）加载资料与工具，每轮再刷新环境和媒体（`_refresh_turn_material`）。阶段结果只交接已有对象，媒体状态由同一工具上下文持有。模型任务在起点按会话与主动回合标志确定，委派子回合用 `task_override` 继承父任务；装配时解析的基础链供窗口估算与工具辅助调用使用，每步模型调用重新读取当前任务链。工具调用/结果写入必须完成后才能释放锁，资产保护覆盖工具返回到父回合提交的间隔。终端保存归 [turn_store.py](../../features/conversation/turn_store.py)，不得把尚未落库的结果留给无所属的后台任务。历史修改入口（压缩、撤回、清空）共享 `compression_context` 的只读拒绝、历史锁与在途回合校验。实时通话独占其会话：通话回合以 `call_owner` 通过同一把会话锁，其他提交与历史修改按 `realtime_call` 拒绝，直到结算完成。

`ephemeral` 用于主动陪伴，请求作为本轮尾部资料，压缩检查点仍保存；`headless` 控制本机桌面工作态，`has_viewer` 控制缓冲和气泡停顿。委派建立父会话下的子会话，继承预设、设置和限制，以 `HeadlessEmitter` 捕获结果；生活空间及再次委派在执行层排除，子会话输入不能成为用户事实证据。

## 提示词与运行时数据

预设决定人格与记忆域，预设、用户开关和本轮状态共同决定工具集合；装配、搜索解锁、披露与派发使用同一资格。工作预设按登记加入双语角色头部，缺少定义明确失败。

陪伴每回合装配统一生活背景，每次模型调用刷新实际呈现资料，窗口/桌面的可见事实由 [companion_actions.py](../companion_actions.py) 投影。普通自动化和子 Agent 不装配陪伴人格及生活空间工具；子 Agent 也不继承实时环境或等待意图。素材查询、动作设计与制作可在空库使用，点播须有当前合格成品，执行时再次核对目标与版本。

日期按用户本地日刷新，历史时刻置于对应发言前；环境、等待和本轮来源资料留在尾部，不进入历史摘要。来源候选及引用绑定由话题模块管理。结构化回复根据音色和可信产物装配，`reply_persona` 独立保存修复所需人设，避免压缩丢失。

推理与交付正文分别保存，只接受完成响应的正文。失败尝试的正文、推理及工具草稿不能进入下一供应商的请求；工具开始和参数增量不代表实际执行。

### 工具披露与记忆访问

首轮披露搜索元工具与等待意图工具（陪伴预设）；陪伴默认媒体集合由 `prompt_presets.py` 定义，其余按域解锁。每次调用前依据真实产物重算可用集合：验图须有就绪图，重做须有当前版本的具体缺陷，再次修正还须有两版间改善的证据。同一父版本复用原修正任务，结果未知只约束相关目标，没有视频任务时不披露查询。

历史解锁不能绕过当前资格。记忆维护政策随 `memory_inspect` 解锁，与独立审阅共用文本；召回与修改只经记忆入口。

搜索工具时，明确的工具名和目录 ID 直接匹配。自然语言查询优先由决策服务在当前工具目录内判断，选择无匹配时返回空候选。服务或判断不可用时使用原有关键词检索。解锁前复核当前工具资格。

## 上下文与记忆

### 摘要边界与原始证据

历史通过 [context_window.py](../../features/conversation/context_window.py) 按消息 ID 读取，`summary_through_message_id` 是真实覆盖边界；无效边界直接失败，分叉与恢复重映射引用，不能按时间猜测。

压缩只处理能完整容纳的历史前缀，不拆消息展开项、并行调用及结果。陪伴摘要保留真实交流和时间，工作/自动化摘要保留工具证据；计数只包含用户发言和助手最终回复。媒体只传引用与未提供内容标记，不把 base64 当文字。检查点交付与保存一致，清理已覆盖历史时仍保护未覆盖媒体。

### 窗口预算与截断

有可靠用量基线时估算增量，否则全量估算，判定阈值由 `turn_inputs.py` 维护。确定性截断优先保留摘要/检查点和最近输入，按调用身份扩展到完整工具批次；连续用户输入使用独立较大预算，删减带原长度标记，重试沿原输入应用同一规则。

保存压缩摘要前，决策服务可用时比对摘要节选和本次被压缩的真实对白。只有证据明确显示关键信息矛盾时才拒绝该摘要，保留原消息。证据来自消息正文，已生成的旧检查点和时间渲染标记不作为原始对白。

实际请求在截断后重新筛选媒体能力，音频原生或转写路径须得到结果或明确错误后继续。按 `multimodal_v1` 还原多模态工具结果。上下文裁剪后的媒体用占位文本表示，缺失工具结果记为未知，调用与结果成对发送。删除提示、日期和时间只能补充上下文，不能替代当前用户请求。

[turn_decisions.py](turn_decisions.py) 依据实际受理的整批文字和同会话近期对白，决定使用当前批次、已有话题或跳过额外记忆召回。召回候选在向量和关键词检索后由决策服务选取，注入前重验作用域、有效期和更新时刻。[原有召回](../../features/memory/memory_retrieval.py) 在服务或判断不可用时继续提供结果。生活和资讯仍获得当前主题资料。

## 回合执行与交付

工具批次仅对白名单只读调用或互不重叠文件操作并发。参数先修复和校验，再派发；错误也成对交付开始/结束事件，不泄露原始异常或用户参数。

循环按 [tool_guardrails.py](../../runtime/tools/tool_guardrails.py) 检查重复失败及调用是否带来了新信息。连续文本查询若改了参数和返回写法，可由决策服务对比脱敏结果的摘录和查询意图；包装与循环提示不作为证据，变化仅出现在摘录之外时不据此判定重复。重复创建完全相同的定时任务或待办时复用本回合的受理结果，修改或取消后可重新创建。两个工具均支持游标翻页。媒体以作品身份和返回状态判断进展。持续无进展时切为无工具最终回复，跨模型保留这一状态。主动回合同样按无进展收束，并受意图有效期约束。

非子 Agent 的陪伴会话执行完整结构校验，校验阶梯（解码 → 演绎降级 → 完整解析 → 恢复预算内降级 → 修正保护）只由 [reply_delivery.py](reply_delivery.py) 的 `resolve_companion_reply` 实现；其他有观看者的回合可流式交付，无头/无观看者回合缓冲正文。文本只按代码围栏外的 Markdown 分隔线分泡，跨 chunk 保留候选前缀。成功、异常及取消都关闭响应流，缓冲正文在释放连接后交付；实际正文交付才锁定供应商回退，恢复资格依链的 `has_next_attempt` 判断。主动联系在链尾因输出 token 耗尽时，使用已有的一次恢复机会降低推理强度，沿用当前工具结果和已交付状态。

即时与延后回复共用回忆核对。`recollection` 台词参考生活快照、实际送达的气泡及本轮查得的资料。网页检索摘要与提取原文保留各自范围。本轮查过生活或日记档案时，普通对白也须在核对后交付。主动分享中需要核对的书面作品按单个文本气泡保留分段、缩进和引用。伙伴画过的草图与实际取得的外部图文各有依据。

直接交流和「换一个回答」可用决策模型筛查普通对白。短对白整体判断，长对白按预算分批并带相邻气泡，跨界的时间、主体和指代可参与判断。模型分别判断是否有往事陈述和是否仅为虚构。任一判断明确要求复核时，先核对证据再交付。通话使用已到达的前文增量筛查，暂缓命中气泡及其后续气泡，终态可增加待核对气泡。已经暂缓的台词交由证据复核结合完整对白处理，虚构内容可原样保留，已入队气泡保持原播放位置。更正台词须通过气泡格式和原文链接校验。普通对白的证据复核失败时，对整批命中的气泡逐句确认，沿原顺序保留可交付的对白和媒体。

通话中的短句闲聊若有充分依据可以直接进入可播放回复。涉及工具、资料核对、往事、附件、承诺或判断不清楚时沿用原工具阶段。

普通定时任务和子 Agent 委派使用本轮工具回执、目标和最后交付判断结果。外部成果须关联所要求的操作及其回执，工具发现结果只供本轮使用。只有明确要求提交本身时才将受理回执计为完成依据。未获视频成品时，状态回执只支持明确要求的查询与报告，不证明成品已取得。决策结果有冲突时保留部分完成、阻塞或待核实状态，决策服务不可用时沿用原结果处理。

陪伴回复允许显式结束为 `quiet`，已持久受理的直接交流还可选择 `defer`。单条文字明确要求不回应且没有待办动作时，决策服务可直接结算沉默。两个结果结束当前回合，延后意图与原消息及提交账本同一事务提交，到期沿原会话重新判断。已受理媒体仍按实际气泡交付，空模型响应按失败处理。格式修复仅接受原稿已明确选择的沉默或延后。延后目的、复查时刻与截止时刻均须可从原稿还原。换一个回答时须产出可交付气泡。陪伴推理只供当前模型执行使用，用户历史保存实际发言和工具结果。

`model_turn.py` 拥有单轮模型回退与恢复：先尝试后续供应商或音频转写路径，链尾共用一次不完整响应重试或格式修复预算，恢复时保留最终回复限定。供应商终态统一经 `response_validation.py` 校验；正文、演绎、媒体引用与修正保护仍归回复交付层。调用用量只统计模型生成与响应消费，包含续轮、格式修复和回退；工具、委派及回合后任务不继承父回合统计。用户错误文案与聊天失败类型归 `turn_errors.py`，英文 detail 仅用于无头结果及诊断；原始请求响应只走显式调试日志。

### 消息与媒体

[reply_media.py](../../features/conversation/reply_media.py) 管理按作品区分的媒体气泡及任务绑定。聊天可分步申请多个画面；同一描述的图片变体组成一个任务，同回合相同请求复用已登记的作品及状态。[attachments.py](../../features/conversation/attachments.py) 管理附件额度和清理。终端持久化合并最新媒体状态，符合资格的用户陪伴回合在提交及完成事件之后才调度心情更新。

[reply_audio.py](../../features/conversation/reply_audio.py) 按消息加锁、固定保存的音色配置，事务外合成后核对原文、语音语义及消息存在性，按气泡序提交并合并最新媒体状态。用户回合先保存回复再合成，主动回合先合成再由意图终态事务保存与投递；取消清理未交接音频。真实格式和时长用媒体检查读取，不能只信扩展名。

## 验证入口

核对实际请求，覆盖完整工具批次、权限、压缩/重试、格式恢复、取消写库、回退锁定和连接关闭；语音与媒体须检查实际交付，解析成功只证明结构可读。
