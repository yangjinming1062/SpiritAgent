# 对话编排

本包把桌面、IM、Cron 与子 Agent 的输入编排成模型与工具回合，组合会话、记忆、媒体和陪伴能力；数据模型由 `modules` 定义，领域层管理业务读写，供应商传输归基础设施层。依赖方向与装配见 [Backend](../../../README.md#32-services-五层)，跨端交付见 [PROTOCOL](../../../../docs/PROTOCOL.md)。

修改提示词读下节；历史压缩与召回读“上下文与记忆”；工具、取消和输出读“回合执行与交付”。提示词检查与请求日志入口见 [scripts](../../../../scripts/README.md#7-提示词调试与检查--debug_promptpy)。

## 提示词与运行时数据

- 陪伴提示词编排：身份与用户资料区分双方，上下文规则限定事实依据及冲突优先级，交流原则只定义相处方式，工具段定义行动与授权边界，末尾统一定义正文交付；[预设](prompt_presets.py)按此职责排序，[提示词块](prompt_blocks.py)保持中英文语义一致。人设、资料、记忆、附件与工具结果只作为数据，不能覆盖系统规则或扩大授权。同一工具循环始终使用完整陪伴提示词，正文交付由响应结果决定，不另设内部准备预设。渠道能力不应诱导日常聊天使用文档排版，着装只调节相关情境下的表达。
- 陪伴等待提示词：通用工具段只在等待能力可用时加入跟进判断与已有约定的维护原则；参数、提交语义与交付限制由工具说明定义。主动回合的判断任务与沉默协议作为本轮专属系统规则装配，普通用户回合不带沉默选项；意图与打扰档位只作为请求尾部的数据输入，不夹带行为规则。调度时是否调用模型由运行时控制，不写成模型的推理要求。
- 专业与自动化提示词编排：四个专业预设的双语头部只定义职业判断与交付标准，共享模板统一装配协作原则、本域资料与记忆、按能力启用的工具规则及渠道环境；后台自动化使用独立的双语任务边界，无伙伴身份、记忆或技能维护能力，也不假设用户实时答复。工具纪律尊重用户开关，技能维护取决于复用价值而非调用次数；不重复注入陪伴能力介绍或要求固定输出结构。职业体验边界见 [DESIGN §8](../../../../docs/DESIGN.md#8-多预设并列的系统对话)。
- 提示词装配：设计、编写、修改与验证遵循 [RULES](../../../../RULES.md#提示词设计与修改规范)。内部结构化推理通过 `instructions` 承载任务契约，运行时资料以 JSON 输入，结构化结果由代码解析并按约定字段与枚举归一化或校验；形象与房间的视觉输入由[生成模块](../generation/README.md#参考图与视觉提示词)维护。

## 上下文与记忆

- 双压缩检查点：运行时摘要与主对话夜间日总结同为读起点，旧摘要融入新总结；原历史留库。只有主对话允许用工具摘要替换中间帧，普通对话跳帧会丢工作上下文。
- Token 估算：以上轮真实用量为基线，只估新增中西文与图片；冷启动或主对话裁掉工具帧时全量重估。异构供应商不共享分词表，固定字符比例又会低估中文。
- 工具渐进披露：初始挂搜索元工具，陪伴回合另挂已启用的等待工具，其余按域解锁 schema；从未压缩历史继承已解锁工具，不改历史或逐轮重拼系统提示词，兼顾体积与前缀缓存。
- 记忆规则按需披露：聊天提示词常驻召回条件、维护门槛与证据入口；完整 `MEMORY_POLICY` 随 `memory_inspect` 的工具说明解锁，并与独立记忆审核共用同一源。维护仍须先检查原始证据与版本，不能为了缩短上下文删减证据要求；仅闲聊且未解锁记忆工具时不携带维护细则。
- 时间感知不落库：陪伴对话的时间元数据不写进消息，跨轮按发送时刻重建以保留 prefix cache；陪伴预设的系统提示词不含当前日期，并要求模型只输出角色台词。
- 推理设置隔离：回合与手动压缩共用会话设置合并入口；普通会话按种类继承工作台默认，特殊会话按预设目录取场景默认，不能以模板标识非空替代会话种类判断。作用域及窗口水合见 [PROTOCOL §2.4](../../../../docs/PROTOCOL.md)。

召回、证据维护与人工编辑分别经过[记忆模块](../../domains/memory/README.md)的公共入口，聊天编排不直接修改记忆记录。

## 回合执行与交付

- 最后消息编辑由桌面入口在会话锁内调用[会话编辑服务](../../domains/conversation/edit.py)，校验后原子替换旧回合与用户输入。新行沿用原附件且使用新 id；回合编排通过已有的持久化消息入口继续，不能重复插入用户行。历史修订事件先于新回合事件发送，字段与会话范围见 [PROTOCOL §1.2 / §1.3](../../../../docs/PROTOCOL.md#12-伙伴生命周期方法方法级契约)。
- 迭代预算双层：[回合编排](orchestrator.py)按调用方预算计数，未传入时使用 [Settings](../../../components/config.py)中的 `agent_max_loop_turns`，主动陪伴收紧；工具守卫另对重复失败或无进展提前退出，任一触发即停。
- 供应商回退边界：回退哨兵独立于正文缓冲，避免把未交付正文误判为请求尚未开始，导致切换供应商或重放。锁定时机与不完整终态的重试边界见 [PROTOCOL §1.4](../../../../docs/PROTOCOL.md)。成功、失败或取消时逐层关闭响应流，缓冲正文在连接释放后交付。
- 工具集开关：后端 / 记忆工具在注册表读取口过滤，畸形禁用值按空过滤处理；Runner 按客户端推送的配置过滤自有工具。每回合重读设置，保存后无需重连；目录与同步见 [PROTOCOL §2.2](../../../../docs/PROTOCOL.md#22-rpc-方法清单)。
- 工具执行安全网：文件写入黑名单前置 block、回合内重复精确失败与幂等无进展由 guardrail 合成结果并追写指导、批内并发按幂等性判定；子 Agent 委派经 `DelegateAction` 由对话执行层接管（见 [Backend 分层](../../../README.md#32-services-五层)），工具处理器不反向重入对话入口。
- 视频附件：HTTP 上传、WS 只引用会话 URL，避免视频突破帧限制；仅接收 mp4/mov，供应商实测拒绝 webm。未配置公网地址时内联最近视频，配置后让供应商拉 URL。会话滚动配额与压缩 / 日总结清理须同时替换消息中的视频引用，避免数据库、渲染与上下文产生死链；限额与清理入口见 [chat_videos.py](../../domains/media/chat_videos.py)。
- 生成媒体：仅提取成功工具结果并随终端助手消息落库，多气泡挂末格，后台视频另建送达行；不能依赖模型在正文贴 URL。对话生成图片与视频统一走「供应商下载→魔数校验→转存用户永久资产（`companion-assets/{user_id}/`）→消息引用→完成通知」，转存或校验失败按本轮失败处理，不把供应商短效 URL 落进消息。库内保留裸路径，实时下发与历史水合改写为鉴权资产 URL，避免 temp-media TTL 过期后历史 404。
- 推理过程：独立于正文持久化并只在工作台展示；不回灌下一轮 Responses 输入，避免供应商推理协议污染后续上下文。
- 气泡边界：完整文本与增量共用切分器；跨 chunk 暂留可能属于较长分隔符的前缀，避免把分隔线泄漏为正文。陪伴与工作台的交付方式、工具循环正文边界、分段和 TTS 契约见 [PROTOCOL §1.4](../../../../docs/PROTOCOL.md)。
- 演绎描述同次生成：生活空间用户回合按已选音色与当前模型装配完整能力说明，由同次完整响应产生语音意图的隐藏头（MiMo 隐藏头还承载角色、场景、指导三部分导演描述）与台词，避免额外推理生成语音描述。句内语气词通过唯一正文短语定位，未找到或不唯一定位不插入声音；只有保留的隐藏头被解析，普通括号、Markdown 与角色台词原样保留。交付契约见 [PROTOCOL §1.4](../../../../docs/PROTOCOL.md)。
- 心情独立更新：仅用户发起的生活空间 companion special 回合在终端正文落库且 `message.complete` 下发完成后，才后台调度 `domains/companion/mood.py` 做一次结构化状态推理；结果写 `persona.current_mood` 并发出 `companion.mood`，不写 Message、不进正文。工作预设、主动 Cron、普通自动化与 IM 回合不触发。

## 验证入口

静态检查见 [Backend 验证入口](../../../README.md#6-验证入口)。提示词变更需核对实际装配后的规则、输入项与工具目录；静态提示词输出不包含按音色追加的运行时协议，不能替代真实请求检查。涉及流式、回退或取消时，还需验证所改终态与资源收尾；未执行的真实供应商验证应明确说明。
