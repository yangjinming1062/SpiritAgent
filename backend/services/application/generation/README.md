# 生成服务

编排形象、外观、房间和媒体生成，管理任务互斥、提交、落库与激活；供应商传输归 infrastructure。参考来源、产物和跨端恢复统一见 [PIPELINE](../../../../docs/PIPELINE.md)，本文只定义内部并发与状态约束。

入口：[形象](avatar_service.py)、[外观](outfit_service.py)、[房间](room_backdrop_service.py)、[模型](model/pipeline.py)、[视频包](video/)、[聊天视频](video_jobs.py)。

## 身份、草稿与并发

头像、全身图、选择和确认共用用户级锁，供应商等待期间不持数据库会话。写入前重新核对当前激活形象、状态和源路径，避免迟到结果覆盖确认或其他重绘。

外观参考立绘确认将草稿转正式资产并锁定身份；允许的参考重绘和种子派生不解锁。草稿路径与画风须可恢复，转存失败可重试；只有全部图片均为过期草稿的头像行才可清理，正式头像或全身参考不能连带删除。

读取后脱离 ORM 再签名，避免把临时 URL 写回资产列。骨架分类首次持久化后由重绘与换装复用，不能反复分类导致画幅翻转。

## 模型任务

模型链复用供应商注册，按持久化阶段恢复；具体提交窗口与重复计费限制见 [PIPELINE](../../../../docs/PIPELINE.md#3-失败与重试语义)。供应商重试与预算在能力链维护，不在各入口另设无限重试。

## 外观确认与激活

外观生成保留草稿行；确认把草稿立绘转正为持久参考图（`ready`），只表示参考图就绪，不触发任何生成，也不自动穿着。重绘成功才替换草稿，落库时核对原状态与源图；状态和刷新事件共同提交，之后清理旧图，冲突时清理本次未采纳产物。

穿着经激活接口显式完成：翻转该用户唯一激活外观，`active` 是当前生效着装描述的唯一权威，供房间 / 出镜媒体生成消费。首次访问可懒建初始外观，其原图归头像行，删除外观不得删除该文件。衣橱命名先读取实际采纳立绘并做视觉转写，再生成名称与描述，覆盖无文字的自备图；
视觉或命名失败保留原名，不用空设计资料生成占位说明。回写核对立绘路径并发送外观更新事件，
迟到命名不能覆盖新图；描述生成失败不阻塞资产就绪。

## 参考图与视觉提示词

参考职责遵守 [PIPELINE](../../../../docs/PIPELINE.md#11-共用参考与种子图派生)，拼图位置与单幅输出规则由 [image_generation.py](image_generation.py)集中处理。全身和外观自备图的宽高比与请求尺寸同源，提示词不另写像素尺寸。

房间简述显式带入性格；用户要求独立传入，不经简述截断。用户参考图须在替换旧 pending 前完成读取、校验并固定为任务输入，后续尝试复用同一份；参考图不独立持久化，任务中断后须重新提交。

在线与夜间房间任务共享互斥与政策检查，但配额分别计算；显式用户请求不占自主配额。换装与房间着装一致性契约见 [PROTOCOL](../../../../docs/PROTOCOL.md#12-伙伴生命周期方法方法级契约)；不从普通生图入口修改当前房间。

## 图像修改双模式（微调 / 重新生成）

`edit` 的能力筛选、前置守卫和失败语义见 [PIPELINE](../../../../docs/PIPELINE.md#111-图像修改双模式微调--重新生成)。编辑提示词共用 `build_image_edit_prompt`，保持条款集中定义且只描述输入图可见属性。

业务服务在读取旧图后选择模式，兼容草稿与正式资产；不能把角色条件化参考当作编辑能力，也不能无提示改走 regenerate。头像、全身参考、外观参考、模型正背面和换装按点位选用保持条款；允许修改头像外貌的条款不能用于换装。全身派生的身份、完整入画及对应视角、姿态、画风和背景要求不因微调而取消。

## 自备图（提示词与采纳）

生成与采纳共用 `_install_fullbody_seed` 等安装入口，保持字段、元数据、事件和旧文件清理一致。契约见 [PIPELINE §1.1.2](../../../../docs/PIPELINE.md#112-用户自备图)；自备图与内部生成共用参考图改写模板，上传沿用既有 MIME、大小和图像校验，不宣称额外完成 AI 身份或内容审核。

房间 `source=user_upload` 的 pending 行不启动生成、不参加 AI 恢复，只由采纳或放弃收敛。

## 限制与验证

视频动作包由 [video/](video/) 编排，按动作保存与恢复结果，两条入口共用交付链：上传导入（`create_pack_from_clips`，源须具有可解码 alpha）与按参考生成（`create_pack_from_reference`，`force=False` 时复用同参考版本的就绪包，不重复触发付费生成）。链路阶段、句柄恢复语义与验收口径见 [PIPELINE §6](../../../../docs/PIPELINE.md#6-视频动作包链)。同一用户同时只允许一个构建中的视频包；切换渲染方式到视频会顺带触发生成（失败只记日志，不阻塞偏好保存）。不能将模型下载恢复保证推广到所有媒体任务。

视频包的生成上下文与动作结果由 [state.py](video/state.py) 显式校验；上传与生成共用动作结果结构，上传包不拥有可重做的冻结参考。

检查命令见 [Backend](../../../README.md#6-验证入口)。验证旧资产保留、并发确认、迟到结果、原任务查询与激活时机；供应商可用性、实际扣费和视觉效果分别报告，不由静态检查推断。
