# 生成服务

本包编排形象、外观、房间和媒体生成，持有任务互斥、付费提交、产物落库与激活流程；供应商传输由 infrastructure 提供，窗口呈现由客户端负责。跨模块的参考图职责、能力链、产物格式与恢复语义以 [PIPELINE](../../../../docs/PIPELINE.md)为准，本文维护后端内部的并发与状态约束。

任务入口包括[形象服务](avatar_service.py)、[外观服务](outfit_service.py)、[房间服务](room_backdrop_service.py)、[3D 管道](pipeline.py)、[2D 编排](mesh2d/)和[视频任务](video_jobs.py)。调整某条链时先读对应约束；2D 模板素材另见[姿态参考](mesh2d/pose-guides/README.md)。

## 身份、草稿与并发

- 身份锁定在服务端执行：确认 2D 全身立绘时草稿转正式资产；锁定后头像与 2D 种子重生成入口拒绝，角色编辑保留既有物种、性别和基础外貌且不重置确认态。独立全身参考与 3D 建模种子的派生不解锁身份，参考规则见 [PIPELINE §1](../../../../docs/PIPELINE.md#1-3d-链拓扑)。
- 形象写入互斥：头像及各类全身图生成、头像选择与确认共用用户级锁，避免迟到生成覆盖确认态或提示词元数据；供应商等待期间不持数据库会话。独立全身参考落库前再次核对当前激活形象，成功替换后清理旧参考文件。
- 草稿可恢复、确认才转正：持久化草稿路径与画风，转存失败可重试；仅全部图片都为过期草稿的头像行可清理，已有正式头像或全身参考时须保留。读取头像与历史时先脱离 ORM 再签名，避免草稿清理的提交把临时签名写回资产列。恢复契约见 [PROTOCOL §1.2](../../../../docs/PROTOCOL.md)。
- 画幅稳定：骨架分类是模型推理，首次分类后随形象持久化，重绘与换装复用，避免多次分类翻转画幅。种子图画风、姿态、参考图及双供应商拆分策略统一见 [PIPELINE](../../../../docs/PIPELINE.md)。

## 2D 与 3D 任务

- 3D 能力链独立于通用 LLM 链，仍复用供应商注册机制；长任务与 web 进程同生命周期，启动扫描未完成记录接续，恢复见 [PIPELINE §3](../../../../docs/PIPELINE.md)。
- 2D 拆分编排：[mesh2d](mesh2d/)持有生成任务、优先级队列、资产落库、外观激活与就绪事件；供应商传输由 [seethrough](../../infrastructure/seethrough/)提供。完整包生成后才发布，交付条件见 [PIPELINE §6](../../../../docs/PIPELINE.md#6-2d-分层动画能力链)。自主视觉动作的公共语义与客户端联动见 [PROTOCOL §1.4](../../../../docs/PROTOCOL.md#14-聊天心情视觉表达与空间契约)。
- 2D 任务排队：当前显示 2D 时优先处理，3D 模式下的备用 2D 生成使用低优先级。不同资产任务独立排队，发布时核对当前身份与穿着意图，避免较晚完成的旧任务覆盖用户选择。
- 2D 失败兜底：生成失败不激活新模型、不自动穿着新外观；已有可用模型继续服务，无可用模型时按 [DESIGN §1.2](../../../../docs/DESIGN.md#12-渲染模式与降级体系永不空白)回退。
- see-through 传输适配：Gradio 入参使用 FileData 对象，裸路径字符串会被静默拒收；魔搭使用 API-Inference 专用域与 Bearer token，不能把 www 代理域当匿名入口。失败统一抛 `SeeThroughError`，由编排层落失败态。产物仅为分层 PSD 字节，后端不解析 PSD，也不依赖 psd-tools；完整资产包生成与发布归 mesh2d。主备切换、单供应商不重试、阶段超时与总预算统一见 [PIPELINE §6.1](../../../../docs/PIPELINE.md#61-psd-链see-through-双-provider)。

## 外观激活与恢复

- 换装两段激活：新建外观时保留当前成功行，新包成功落库时才原子翻转；用户中途手动换装会清除自动穿着意图。校验和所有翻转共用用户级锁，避免并发确认产生重复付费任务；激活查询只认成功行。
- 外观重绘恢复：失败外观可回到设计流程，重绘成功才替换为草稿，生成失败保留原立绘与状态；提交重绘结果前在锁内刷新并核对原状态及立绘路径，避免覆盖并发确认或另一轮重绘。状态与衣柜刷新事件同事务提交，提交后清理被替换的立绘；并发校验拒绝时清理本轮生成图片。重试与资产完整性见 [PIPELINE §6.2](../../../../docs/PIPELINE.md#62-扶边姿态包)。
- 衣柜预览：列表批量查询每套外观最新的成功 2D 行，复用桌面资产签名与序列化；查询按用户及外观归属隔离，无需激活即可预览，契约见 [PROTOCOL §1.2](../../../../docs/PROTOCOL.md)。
- 衣柜归属：首次访问懒建初始外观并回填归属；初始立绘归头像行，删除外观不能删其文件。换装不受身份锁阻挡，服装 / 发型可换，五官 / 身材由独立全身种子图锚定（其身份源自确认头像）；独立小时频控，不限衣柜数量。
- 着装感知：后台生成着装描述，失败不阻塞就绪；对话与触摸反应共用当前着装上下文，性格主导行为、着装只调节表达。

## 参考图与视觉提示词

视觉提示词按 [PIPELINE §1.1](../../../../docs/PIPELINE.md#11-共用参考与种子图派生)装配参考图职责；拼图位置与单幅成图要求由[生图适配层](image_generation.py)统一说明，避免各业务入口重复拼装。提示词维护遵循 [RULES](../../../../RULES.md#提示词设计与修改规范)。

- 房间生成：性格须显式进入房间简述，参考像素不能表达性格；明确的房间要求独立传给生图模型，不经简述截断，优先于陈设与光线建议但不覆盖身份、穿着和画面约束。普通会话生图不得修改激活背景。在线自主换房受用户锁、日配额与打扰档位约束，夜间共用互斥和政策锁但不占在线配额；用户请求与换装失效的保护规则见 [PROTOCOL](../../../../docs/PROTOCOL.md)。
- 房间参考图：在取代旧 pending 前读取、校验并固化为任务内图片，全部尝试复用同一份参考；用户任务中断后需重新提交，参考图不单独写入永久资产或备份。身份图和用户图的职责与供应商提交方式归 [PIPELINE §1](../../../../docs/PIPELINE.md#1-3d-链拓扑)，聊天图片选择与用户请求门控归 [PROTOCOL §1.2](../../../../docs/PROTOCOL.md#12-伙伴生命周期方法方法级契约)。

## 限制与验证

- see-through 依赖社区免费算力、无 SLA：休眠唤醒与排队延迟不可消除，由阶段超时与总预算显式降级（编排层落失败态，客户端渲染级联降级并可在设置页重试）；需要稳定服务时经 `seethrough_space_base` / `seethrough_fallback_base` 切换专用部署或自托管入口。
- 后台视频下载中断后不可自动恢复：供应商产物地址短时效，重启后处于下载阶段的任务直接标记失败，由用户重新生成；`queued` / `processing` 状态的任务仍会接续轮询。

静态检查见 [Backend](../../../README.md#6-验证入口)。修改生成链需针对涉及的成功、失败、中断与迟到结果检查：旧资产是否保留、任务能否核对、是否会重复提交、何时才允许激活。供应商可用性、真实扣费与渲染效果需按实际执行范围报告，不能从静态检查推断。
