# 生成服务

编排形象、外观、房间和媒体生成，管理任务互斥、提交、落库与激活；供应商传输归 infrastructure。参考来源、产物和跨端恢复统一见 [PIPELINE](../../../../docs/PIPELINE.md)，本文只定义内部并发与状态约束。

入口：[形象](avatar_service.py)、[外观](outfit_service.py)、[房间](room_backdrop_service.py)、[3D](pipeline.py)、[2D](mesh2d/)、[视频](video_jobs.py)；姿态提示词与背景策略装配见 [mesh2d/poses.py](mesh2d/poses.py)。

## 身份、草稿与并发

头像、全身图、选择和确认共用用户级锁，供应商等待期间不持数据库会话。写入前重新核对当前激活形象、状态和源路径，避免迟到结果覆盖确认或其他重绘。

2D 立绘确认将草稿转正式资产并锁定身份；允许的参考重绘和 3D 派生不解锁。草稿路径与画风须可恢复，转存失败可重试；只有全部图片均为过期草稿的头像行才可清理，正式头像或全身参考不能连带删除。

读取后脱离 ORM 再签名，避免把临时 URL 写回资产列。骨架分类首次持久化后由重绘与换装复用，不能反复分类导致画幅翻转。

## 2D 与 3D 任务

3D 复用供应商注册，按持久化阶段恢复；具体提交窗口与重复计费限制见 [PIPELINE](../../../../docs/PIPELINE.md#3-失败与重试语义)。

2D 编排管理队列、分支、入库和事件，传输由 [seethrough](../../infrastructure/seethrough/)提供。当前 2D 显示任务优先，备用生成低优先级；完整包就绪后才发布，并再次核对身份和穿着意图。失败不激活新资产。

see-through 的 Gradio 入参必须使用 FileData，魔搭使用专用 API 域与 Bearer。错误统一交给编排落状态。拆分结果只是候选分层：发布前由 [mesh2d/appearance](mesh2d/appearance/README.md) 解析 PSD（psd-tools）执行原图锁定重建与外观门禁，未通过不发布；诊断产物与验收口径见其 README。供应商重试与总预算在能力链维护，不在各入口另设无限重试。

## 外观激活与恢复

外观生成保留当前成功行，新包成功后在用户锁下原子翻转；用户手动换装会清除旧自动穿着意图。重绘成功才替换草稿，落库时核对原状态与源图；状态和刷新事件共同提交，之后清理旧图，冲突时清理本次未采纳产物。

衣橱列表按用户和外观批量读取最新成功包，预览不激活。首次访问可懒建初始外观，其原图归头像行，删除外观不得删除该文件。着装描述生成失败不阻塞资产就绪。

## 参考图与视觉提示词

参考职责遵守 [PIPELINE](../../../../docs/PIPELINE.md#11-共用参考与种子图派生)，拼图位置与单幅输出规则由 [image_generation.py](image_generation.py)集中处理。全身和外观自备图的宽高比与请求尺寸同源，提示词不另写像素尺寸。

房间简述显式带入性格；用户要求独立传入，不经简述截断。用户参考图须在替换旧 pending 前完成读取、校验并固定为任务输入，后续尝试复用同一份；参考图不独立持久化，任务中断后须重新提交。

在线与夜间房间任务共享互斥与政策检查，但配额分别计算；显式用户请求不占自主配额。换装与房间着装一致性契约见 [PROTOCOL](../../../../docs/PROTOCOL.md#12-伙伴生命周期方法方法级契约)；不从普通生图入口修改当前房间。

## 图像修改双模式（微调 / 重新生成）

`edit` 的能力筛选、前置守卫和失败语义见 [PIPELINE](../../../../docs/PIPELINE.md#111-图像修改双模式微调--重新生成)。编辑提示词共用 `build_image_edit_prompt`，保持条款集中定义且只描述输入图可见属性。

业务服务在读取旧图后选择模式，兼容草稿与正式资产；不能把角色条件化参考当作编辑能力，也不能无提示改走 regenerate。

## 自备图（提示词与采纳）

生成与采纳共用 `_install_fullbody_seed` 等安装入口，保持字段、元数据、事件和旧文件清理一致。契约见 [PIPELINE §1.1.2](../../../../docs/PIPELINE.md#112-用户自备图)；自备图与内部生成共用参考图改写模板，上传沿用既有 MIME、大小和图像校验，不宣称额外完成 AI 身份或内容审核。

房间 `source=user_upload` 的 pending 行不启动生成、不参加 AI 恢复，只由采纳或放弃收敛。

## 限制与验证

see-through 社区算力无 SLA，通过阶段超时和总预算失败收敛；需要专用服务时修改配置入口，而非无限延长等待。

后台视频下载阶段中断后当前不可自动恢复，重启按失败处理；queued / processing 仍可续轮询。不能将 3D 下载恢复保证推广到所有媒体任务。

检查命令见 [Backend](../../../README.md#6-验证入口)。验证旧资产保留、并发确认、迟到结果、原任务查询与激活时机；供应商可用性、实际扣费和视觉效果分别报告，不由静态检查推断。
