# 正式资产生命周期

统一管理数据库业务引用和 `companion-assets` 文件的回收。文件布局助手与写入保护归 [infrastructure/assets](../../infrastructure/assets/)，跨层路径校验归 [asset_paths](../../../components/asset_paths.py)；供应商取消由应用层负责。接口见 [`__init__.py`](__init__.py)，存储与删除契约见 [PROTOCOL](../../../../docs/PROTOCOL.md#资产访问与缓存)。

- 删除历史前调用 `collect_message_asset_releases` 登记释放并移除对应媒体事件；锁顺序为用户源消息、视频任务、助手回复，删除失败或回滚不触碰正式文件。提交后入口先取消并等待对应视频和语音任务，再执行 `cleanup_user_media` 收尾。
- `collect_live_asset_paths` 汇集原文、工具结果、结构化回复、独立资产、可恢复任务和待投递事件，按账户校验完整路径。当前动作目录以及播放保护期内的旧目录均展开其引用；目录不可读时整账户停止文件回收。
- 回收分为待办事务、资产锁内的一致快照复查与文件删除、结果事务，避免持文件锁等待制作流程持有的业务行锁；PostgreSQL 复查使用可重复读，防止采纳在两个表的查询之间转移引用而被漏读。文件已经消失但结果未提交可重复执行；失败保留路径、次数和诊断。
- 写入租约继承当前业务任务，覆盖子工具返回到父回合提交之间的窗口；独立后台生成使用独立任务归属。协程完成后自动释放，非协程写入必须显式释放。派生历史在同一用户资产锁下复制引用；直接复制旧文件引用的新增入口也须使用该锁。
- 待采纳结果与可重试候选持有文件，终态全身候选回收；事件持有、保留期与计额去重记录规则见 [PROTOCOL](../../../../docs/PROTOCOL.md#资产访问与缓存)。
