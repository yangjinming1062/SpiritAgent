# 实时语音通话

本模块拥有实时通话的传输协议、会话生命周期和音频回合代次。它与普通语音消息的录音上传、整段 STT、TTS 播放分开；连续音频只在内存中经过通话回调，不直接写入会话历史。已声明流式能力的供应商走持续 ASR/PCM TTS，未声明时保留明确的整段兼容路径。

`contracts.py` 定义控制事件、PCM 帧和通话状态。`session.py` 的 `CallManager` 管理账户通话互斥。`turn_seq` 和 `playback_epoch` 隔离插话前后的回合和播放回执。`workflows/realtime_voice.py` 在最终识别后提交聊天，输入溢出时作废当前发言。静音撤销未提交的麦克风输入，挂断等待本次通话回合的收尾。

默认音色在提示词装配时优先选择具备流式能力的供应商。已确认的音色沿用媒体层解析和资产保护，流式能力缺失时走整段合成。工具决策阶段可连续调用工具，确认收束后再流式生成最终回复。`dialogue` 气泡按终态规则分句、绑定音色，按顺序进入有界交付队列。`written` 回复在完整校验后交付。

交付队列关闭后，等待入队和等待回执的任务均可收尾。完整播放或显示的气泡归当前请求；挂断或插话时已经开始播放的当前气泡按整句与已确认气泡一起保留，历史事务成功后才从交付记录移除。整段降级在内存中解码并播放，确认交付后的台词通过现有聊天事务关联至通话记录。工具操作按其真实结果收尾。

`workflows/realtime_voice.py` 复用聊天受理与结算入口，只向通话连接发布回合状态。

HTTP 入口在 `backend/entrypoints/http/routes/realtime_voice.py`，复用网关一次性票据和会话归属校验，JSON 控制帧与二进制音频帧不混入现有 JSON-RPC 网关。
