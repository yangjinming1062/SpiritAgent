# 实时语音通话

本模块拥有实时通话的传输协议、会话生命周期和音频回合代次。它与普通语音消息的录音上传、整段 STT、TTS 播放分开；连续音频只在内存中经过通话回调，不直接写入会话历史。已声明流式能力的供应商走持续 ASR/PCM TTS，未声明时保留明确的整段兼容路径。

`contracts.py` 定义 JSON 控制事件、二进制音频帧和通话状态；`session.py` 的 `CallManager` 保证同一账户只有一通活动通话，`turn_seq` 标识用户回合，`playback_epoch` 标识当前有效播放，并限制输入速率、输出积压和播放确认。插话会同时推进两者，使迟到的模型或媒体结果失效。`workflows/realtime_voice.py` 持续接收 PCM，优先消费流式识别的临时/最终结果；只有最终识别句子才提交为用户发言，临时文本仅用于界面预览。输入队列溢出会使当前发言失效并要求重新开始，不会静默丢帧后继续提交。通话语音在未指定固定音色时优先使用 Mimo、MiniMax；流式筛选后由实际支持能力的 MiniMax 输出，Mimo 负责整段或兼容回退。结构化 `dialogue` 回复先按终态规则分句并绑定音色；`written` 回复不走逐气泡增量路径。工具可用时先运行不交付台词的工具决策阶段，随后进入无工具的最终回复流；无工具或最终回复轮通过有界气泡队列提前交付文字或语音，避免把工具轮正文误认为正式台词。已提前确认的气泡在插话、供应商错误或正常收尾时通过同一交付账本写入历史。流式输出在播放确认后尽力保存实际 PCM 资产；资产保存失败不抹掉已发生的交流事实。自定义音色先复用媒体层的解析和资产保护，供应商不支持该音色的流式协议时明确回退整段路径；工具执行的真实副作用不由通话中断回滚。

`workflows/realtime_voice.py` 复用普通事件发布器和聊天提交入口；通话断开不会让已受理的普通回合失败。

HTTP 入口在 `backend/entrypoints/http/routes/realtime_voice.py`，复用网关一次性票据和会话归属校验，JSON 控制帧与二进制音频帧不混入现有 JSON-RPC 网关。模型适配和历史保存必须继续遵守 `docs/PROTOCOL.md` 的实时通话契约。
