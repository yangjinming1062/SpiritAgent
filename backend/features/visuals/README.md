# 影像库

负责可播放视觉成品、制作工作项、舞台呈现与播放账本。

## 资产分类

成品按 `asset_kind` 分 `actor` / `scene` / `cinematic` 三类，共用一份身份与不可变版本结构，差别由冻结输入的判别联合（`snapshot_json.source.kind`）承载。动作定义是语义层，一个动作可拥有多个媒体实现（不同造型/不同形式），动作详情经 `by-action` 端点查询已制作清单。

## 成品与任务

用户制作先由 `interpret.py` 在候选素材内整理成计划，不写库也不受理；候选由 `workflows/visuals_companion.py` 按描述关键词预筛自数据库，每类有上限并可靠判断命中是否还有更多；命中未覆盖该类全部素材时补读最新一页并标记目录不完整，不把检索未命中误判成没有素材；从环境详情发起的动态制作直接读取指定环境，不受候选目录影响。确认后经 `workflows/visuals_companion.py` 复核归属与就绪状态再冻结素材，图片/视频共用现有工作项。原件分析期间使用 `source.kind=analysis` 暂存，完成后转为普通的 actor/scene/cinematic 来源；基础文件校验通过即具备收藏资格，收藏资格与自动演出资格分开，上传和生成共用成品模型与规则。上传界面只需提交原件，分析得到的标题和描述在完成时写回成品；上传原件的呈现审核只更新自动演出资格，不创建原件候选，素材归属有歧义时可在详情修正。分析期间的临时标题仅用于列表识别。分析结果由 `visual_import_jobs` 持久保存，`selections_json` 保存含操作身份的条目队列，分析事实与响应投影分别建模，条目的操作状态、执行阶段和可用操作由队列与业务结果投影，业务结果不保存执行阶段；`import_operations.py` 定义队列、状态推导与恢复动作判定，`import_jobs.py` 在事务内领取、合并单条进度并保留新入队项，提交成功后才推进内存修订。队列清空后的呈现审核与发布须再次核对队列，新增操作使旧审核失效；原件恢复为普通成品且没有待确认素材操作时自动发布。处理后的主体媒体完全通过时自动发布；身份和目标已通过、仅画质存疑时，用户可在详情选用。处理失败保留上传原件。原件和已分析版本共用既有成品与版本附件；分析发布归 `import_publication.py`。详情的 `auto_play_blocks` 由 `eligibility.py` 与导入结果共同投影，必须和自动目录及播放入口共用资格判断，不允许客户端自行推导或绕过。

调用方装配三类资产的冻结输入，动作语义及呈现选择来源须按契约完整保存；读取和恢复共用结构校验。本模块不跨域读取素材 ORM。请求身份与冻结输入分别去重；手动制作由客户端保留请求身份，响应丢失后沿原请求核对，不能重新付费提交。环境静态图直接复用环境素材，受理端只制作环境循环视频，制作请求可带可选 `day_phase` 冻结适用时段：复用可恢复图片链先准备对应光线的起始图，再设计环境循环；复核同时读取原环境、起始图与视频抽样；它与角色视频共用队列、候选选择和恢复流程，按环境抽样复核，不做人物身份检查。导入上下文保存冻结身份、抽样与检查依据、选定素材及按条目标识登记的创建归属；完整可用素材目录仅在本次执行内读取，不写入每次进度。重新分析保留创建归属。导入关联修改会保留本次创建过的素材归属；撤销或切换前由 workflow 检查影像、生活和当前任务引用，仍被共享时只解除本次关联，不删除素材。

`publication.py` 组合业务采纳与公共任务完成守卫，核对目标和预期版本后追加不可变版本、切换当前指针并登记资产；调用方在同一采纳事务经 `life.py` 结算关联步骤。完整场景和环境视频可先采纳起始图，主体动画只保留真实输入图的文件引用，不创建主体图片成品。重做失败、暂停或取消保留旧成品。按版本预览同时校验账户、成品和版本归属。

主体起始图优先复用造型原像素并补纯色画布；视频请求直接使用基于合格首帧设计的运动，保留明确要求，固定该景别与幕布；活动需要重新准备时仍直接读取冻结的身份与造型，避免沿派生图逐轮重画。复用与生成共用起始图和活动准备检查，恢复沿已保存的图片与供应商档位继续。

生成主体视频按固定帧率逐帧分割并估计边缘 alpha 与前景颜色；原生透明的用户视频保留实际 alpha 并作逐帧检查，二者都用确认后的 RGBA 帧编码 WebM，原件另存；遮罩时间与交付视频对应，首末帧、遮罩及锚点写入版本 `body_json`，并以版本附件保护文件。边界和底部支撑锚点来自真实 alpha，头部锚点随视频复核读取实际首帧，无法确认则留空。处理链见 [actor_clip.py](../../infrastructure/video_processing/actor_clip.py)。自动使用的文件、合成数据与语义资格统一由 [eligibility.py](eligibility.py) 校验；成品检查依据随冻结快照保存，任务检查点回收不清除该依据。

基础准备由 [visual_preparation.py](../../workflows/visual_preparation.py) 协调。首次就绪、造型实际采用与维护恢复触发准备，沿现有合格成品或原任务继续。待机就绪后优先准备安睡和醒来。配对的醒来工作项冻结合格睡姿首帧的路径和摘要，稳定请求身份同时绑定该帧；任务和成品的资产关系持有该引用。待机缺少合格成品、工作项失败、暂停或结果未知时，本轮交回原恢复入口；渐进动作仅未达自动演出资格时，保留成品并继续，安睡缺少合格首帧时跳过醒来。基础准备使用 `base_preparation` 来源和现有供应商预算，不装配生活策划资料或登记生活步骤。

制作由 `TaskScope` 按工作项单飞，输入准备、动作规划与视频制作分别协调；图片完成输入准备后直接发布，不建立视频尝试。视频阶段接入公共队列和结果接收操作；按工作项、制作代次与供应商次序找回已登记尝试，登记后检查点保存中断不重新付费提交。列表与详情实时投影权威尝试进度。业务保留自己的采纳条件，不改写调用方的生成要求。当前候选及其 `VisualReview` 归制作进度，切换后才归入链的候选历史；人工选择历史候选时移回当前，两处不同时持有同一候选。身份、目标与质量结论只读取 `VisualReview`，独立请求的冻结证据保留到所有维度明确，再合并归入检查结果；起始图片检查与视频检查分别保存。临时检查故障可沿冻结证据有限续审。伙伴自主制作失败会结算原生活步骤并保留旧作品。用户发起的制作仅在身份与目标合格、画质存疑时保留可选候选，由详情中的业务操作核对版本后采纳或重做。列表与详情共用检查依据，不补造缺失判断。

## 呈现与文件

呈现读取指定的冻结版本，素材修改或重做不能追改已显示的事实。呈现行保存舞台组合 `composition_json`、账户级默认壁纸关系 `default_visual_id`、生活意图 `intent_json`、静态目标与已显示快照、待播指令和代次。默认关系按稳定影像 ID 保存并跟随该条目的当前版本；用户从影像详情指定或清除，只允许 `scene` 与 `cinematic` 的已审核持续成品。

`stage_plan` 从当前生活修订、账户作息、已采用造型和可播版本推导。已知且唯一的场景名称可定位环境素材。透明主体的外部道具条件需有当前环境依据，完整影像自带环境；只有白天版环境时，夜间选择中性版本或原环境静图。候选按实际活动、时段和素材审核结果筛选，保留同一活动的多个不同版本。安睡优先采用有真实首帧来源可接续的动作组合，起身素材以对应作息事件和有效期交付。桌面使用舞台计划选择日常画面，从 `ambient_catalog` 取直接互动的短动作。制作只读取开关与目标画幅，静态恢复单独核对冻结素材与待机库存。

`composition.media` 和播放指令附可播版本及角色锚点。`default_wallpaper` 是桌面基础回退。用户点播经指定版本的指令、认领和实际回执记账；作息、日常循环与本地换片随呈现计划生效，逐圈播放由客户端管理。静态兜底由 [life_presentation](../../workflows/life_presentation.py) 冻结，静态回执跟踪正式静态目标的加载结果。

`notify_visuals_updated` 通知库、任务和生活意图投影变化，但不推进呈现修订；正式呈现经 `touch_presentation` 及回执推进，制作进度和意图刷新不能使在途播放认领失效。

静态呈现冻结已有素材，不创建影像成品。上线、重连及模式变化通过 `companion_signal` 恢复：事务内重绑当前生活修订及新请求身份，成功才消费在线代次；有效待播指令优先，并发恢复复用已有目标。窗口宿主不接收完整场景恢复指令，改由当前身份与造型可用的透明主体或静态目标承载。缺少素材只产生准备状态，不记录为已显示伙伴。

内部快照保留裸路径，HTTP 与事件出口统一经 `client_assets.py` 转换地址且不修改冻结来源。列表使用摘要与 ID 游标，可播目录在数据库筛选；制作输入与候选由公共任务资产关系保护，导入原件、候选和复核资料使用随分析任务保留的引用并在保存事务精确替换。条目完成后释放落选候选，保留已采用素材与检查依据；待处理或提交结果未知的链继续完整保留。呈现结果采纳后由版本资产关系持有素材引用，分析任务不再重复保留同一批文件。已发布文件由版本资产关系保护；尚无版本关系的静态呈现冻结引用仍扫描其 JSON。回收核对当前版本、舞台组合各层版本、呈现、播放和任务引用。

## 恢复与验证

已删除来源保留描述和文件、来源 ID 留空，避免误绑定新身份；历史成品仍可查看，重做使用当前有效角色资料。未知提交保留原任务核对终态。

核对请求重放、共享步骤、发布并发、重做与旧回执、静态恢复、账户/模式切换和资产保护；真实视频接续、图片显示与供应商质量分别验收。
