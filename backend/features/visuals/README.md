# 影像库

负责可播放视觉成品、制作工作项、舞台呈现与播放账本。跨端资格、回执和恢复见 [呈现契约](../../../docs/PROTOCOL.md#影像成品与模式隔离)，制作规格见 [组合影像制作](../../../docs/PIPELINE.md#组合影像制作)。

## 资产分类

成品按 `asset_kind` 分三类，共用一份身份与不可变版本结构，差别在冻结输入的判别联合（`snapshot_json.source.kind`）：

| 类型 | 冻结输入 | 用途 |
|---|---|---|
| `actor` | 身份 + 造型 + 动作，不绑定环境 | 透明主体动画；窗口精灵直接播放，桌面合成到环境层；版本另存主体元数据 `body_json`（遮罩/首末帧/锚点/命中区域） |
| `scene` | 单张环境素材 | 环境媒体；静态图即素材本身，循环视频以环境图为首尾帧制作，无人物与动作绑定 |
| `cinematic` | 身份 + 造型 + 环境 + 动作整体组合 | 完整场景影像；直接作为主画面，不强制透明处理 |

动作定义是语义层，一个动作可拥有多个媒体实现（不同造型/不同形式）；动作详情经 `by-action` 端点查询已制作清单。不同造型不默认共用同一角色视频。

## 成品与任务

调用方装配三类资产的冻结输入，本模块不跨域读取素材 ORM。请求身份与冻结输入分别去重；手动制作由客户端保留请求身份，响应丢失后沿原请求核对，不能重新付费提交。环境静态图直接复用环境素材，受理端只制作环境循环视频；它与角色视频共用队列、候选选择和恢复流程，按环境抽样复核，不做人物身份评分。

`publication.py` 组合业务采纳与公共任务完成守卫，核对目标和预期版本后追加不可变版本、切换当前指针并登记资产；调用方在同一采纳事务经 `life.py` 结算关联步骤。完整场景和环境视频可先采纳起始图，主体动画只保留真实输入图的文件引用，不创建主体图片成品。重做失败、暂停或取消保留旧成品。

主体视频按固定帧率逐帧抠像并用处理后的 RGBA 帧编码 WebM；遮罩时间与交付视频对应，首末帧、遮罩及锚点写入版本 `body_json`，并以版本附件保护文件。边界和底部支撑锚点来自真实 alpha，头部锚点随视频复核读取实际首帧，无法确认则留空。处理链见 [actor_clip.py](../../infrastructure/video_processing/actor_clip.py)。

基础准备由 [visual_preparation.py](../../workflows/visual_preparation.py) 协调：只为已采用造型（首次无呈现时取初始造型）准备待机、注意用户和舒展，先复用身份、造型及动作版本相符的成品；待机成功后再继续少量反应。工作项来源 `base_preparation` 与自主制作分开，不读取生活策划资料、不创建生活步骤或经历，共用现有有限修复与供应商预算。实际身份、造型图片与动作内容派生稳定请求身份，描述更新、重启及重复通知不重置额度；失败、暂停和未知等待原任务恢复，不自动新建替代任务。新造型仅入柜不触发准备，实际采用、首次就绪与维护恢复才请求准备。

制作按工作项单飞，视频阶段接入公共队列；共享供应商等待与未知结果规则归 [PIPELINE](../../../docs/PIPELINE.md#全局视频队列)。业务保留自己的采纳条件，不改写调用方的生成要求。

## 呈现与文件

呈现读取指定的冻结版本，素材修改或重做不能追改已显示的事实。呈现行保存舞台组合 `composition_json`（layered 引用环境层与主体层 / cinematic 整片引用，互斥）与生活意图 `intent_json`（生活侧只写投影，含结构化活动类别，呈现系统只读取）；两者是呈现配置，不构成第二份生活事实。开播回执按成品类型推进组合：actor/scene 各自替换所在图层，cinematic 整片接管。呈现响应在 `composition.media` 附各层可播媒体投影（含 actor 版本的 `body` 锚点与命中元数据），播放指令对 actor 成品同样携带 `body`；`ambient_actor` 从已有待机成品中匹配冻结身份和造型，`ambient_catalog` 另投影当前身份与造型可用的主体动画与完整场景影像（含冻结动作属性、实际媒体语义及适用条件），供客户端导演按活动类别结构化匹配并本地选择常驻轮换，两者不制作新素材、不建立逐圈播放账本；窗口模式播放透明主体视频按 `video` 回执并推进组合，静态投影仍按 `window_static`。客户端导演点播（`POST /{visual_id}/play`，desktop 身份）走同一指令管线，受理时核对目标媒体与舞台冻结身份、造型一致。

生活情境投影与静态兜底归 [life_presentation](../../workflows/life_presentation.py)：动态表现关闭或无可播媒体时生活变化只落到静态目标，自主播放与制作的档位闸门不变。

`notify_visuals_updated` 通知库、任务和生活意图投影变化，但不推进呈现修订；正式呈现经 `touch_presentation` 及回执推进，制作进度和意图刷新不能使在途播放认领失效。

静态呈现冻结已有素材，不创建影像成品。上线、重连及模式变化通过 `companion_signal` 恢复：事务内重绑当前生活修订及新请求身份，成功才消费在线代次；有效待播指令优先，并发恢复复用已有目标。缺少素材只产生准备状态，不记录为已显示伙伴。

内部快照保留裸路径，HTTP 与事件出口统一经 `client_assets.py` 转换地址且不修改冻结来源。列表使用摘要与 ID 游标，可播目录在数据库筛选；回收核对当前版本、舞台组合各层版本、呈现、播放和任务引用，保留范围见 [必要历史](../../../docs/DATABASE.md#必要历史)。

## 恢复与验证

恢复先重映射物理关系和冻结素材（判别联合按 `source.kind` 分支重映射 outfit/scene/action 引用），再重映射组合各层成品身份并重建呈现快照、作废旧指令与回执；组合媒体投影不随备份恢复。已删除来源保留描述和文件、来源 ID 留空，避免误绑定新库身份；历史成品仍可查看，重做使用当前有效角色资料。未知提交沿 [备份契约](../../../docs/PROTOCOL.md#备份校验与覆盖恢复) 保留原任务。

按 [Scripts](../../../scripts/README.md) 核对请求重放、共享步骤、发布并发、重做与旧回执、静态恢复、账户/模式切换和资产保护；真实视频接续、图片显示与供应商质量分别验收。
