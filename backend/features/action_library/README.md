# 共享动作目录

拥有同着装自定义动作的定义、语义评审、复用关系和各目标调度意图。窗口动作与桌面生活分别拥有素材、制作状态、采纳和播放；跨模块编排归 [action_library.py](../../workflows/action_library.py)，全局行为归 [动作契约](../../../docs/PROTOCOL.md#动作目录与播放)。

## 入口与边界

| 入口 | 职责 |
|---|---|
| [models.py](models.py)、[schemas.py](schemas.py) | 稳定定义、独立目标、冻结来源和版本摘要 |
| [service.py](service.py)、[review.py](review.py)、[queries.py](queries.py) | 受理去重、独立评审、复用及可见进度 |
| [identity.py](identity.py)、[ports.py](ports.py) | 原始视觉来源键与显式装配的目标读取、调度端口 |
| [backup.py](backup.py)、[asset_references.py](asset_references.py) | 关联重映射、手动恢复与冻结参考资产引用 |

同账户、同着装和相同原始身份/着装来源才共享定义，原始来源键不依赖数据库 ID 或存储路径。不得用对齐参考或桌景成品判断来源是否一致。统一定义保留核心动作和必要道具，目标分别拥有衔接与触发设置，可按环境调整构图与姿态，分别生成图像和视频。伙伴的当前能力与工具由 [统一视图](../../workflows/companion_actions.py) 投影，设计评审不依赖伙伴选择呈现模式。

## 调度与恢复

受理锁和唯一约束收敛重复定义及目标。批准后持久化目标调度意图，提交后才启动制作；已存在的成品和任务不重复提交。手动目标与已提交任务明确分开，删除版本留下排除记录，自动同步不复活该版本。来源缺失或不匹配时保留成品并显示受阻原因。

同一着装来源的语义评审串行，等待期间不持数据库连接；模型提交前持久记录 `reviewing`，中断后转为需手动处理的暂缓，不自动重新付费。目标创建及基准就绪事务同时登记调度意图，提交后回调丢失时按待处理目标恢复，不扫描或补做历史素材。

各模式仅播放其本地已就绪版本，制作进度通过共同定义关联。备份按着装、定义、两端容器与动作、目标成组校验和恢复，所有 ID 按所属模块重映射；排除状态保留，其他调度意图恢复为手动，未完成评审暂缓，恢复不启动付费制作。冻结评审参考独立持有资产引用。
