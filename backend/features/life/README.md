# 生活状态

拥有账户生活状态、持续事项、执行步骤和事件。事实性质、事项转换、额度及完成边界见 [生活契约](../../../docs/PROTOCOL.md#生活状态与生活事件)，字段归属见 [字段字典](../../../docs/DATABASE_FIELDS.md#生活夜间与调度)。

`context.py` 为推理入口提供共同快照，保证聚焦事项不会被分页挤出；`queries.pursuit_evidence` 补充未解决步骤和可引用事件。模型通过 `prompt_payload` 消费内容、时间和证据身份，执行参数与存储元数据不进入表达上下文；`prompts.py` 集中维护事实说明和内容投影。

`use_cases.commit_decision_in_session` 在调用方事务内提交状态、事项、事件和 outbox；步骤创建、认领及结算共用账户生活状态锁。业务受理事务须调用 `require_step_submission` 复核事项，采纳事务经 `settlement.py` 批量结算共享步骤。`actions.py` 定义执行输入与永久阅读成果，`execution.py` 管理认领、额度和检查点，`lifecycle.py` 管理事项转换；跨域编排归工作流 `life_execution.py`。

`backup.py` 重映射输入、成果和证据引用；独立额度记录只合并，不随覆盖恢复删除。已提交请求保留未知结果；仅认领、尚未受理的步骤可沿原身份继续执行。公开详情省略阅读原文，永久成果保留实际读取范围与正文。

有意义事件经装配端口投影为带 `source_event_id` 的系统记忆。批量投影使用嵌套事务，失败后逐条隔离重试，索引失败不回滚业务成果。跨模块使用公开用例、执行入口、查询 DTO 和装配端口，不读取外域 ORM。

事项与事件列表使用时间戳和 ID 的稳定游标，精确总数显式请求时额外查询一次。生活上下文不调用带总数的列表入口。事项按更新时间排序，事件按发生时间排序；同时间戳用 ID 消歧义。
