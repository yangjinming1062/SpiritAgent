# 生活状态

拥有账户生活状态、持续事项、业务步骤关联和事件。全局事实与完成边界见 [生活契约](../../../docs/PROTOCOL.md#生活状态与生活事件)；`context.py` 为各推理入口提供共同快照，并保证聚焦事项不会被分页挤出。`queries.pursuit_evidence` 按事项补充未解决步骤与可引用的结果事件；模型输入经 `prompt_payload` 去除调度、幂等键等存储信息，保留内容、来源、发生时间和结果依据。

`use_cases.commit_decision_in_session` 在调用方事务内统一提交状态、事项操作、事实和 outbox，调用前与提交前各验一次账户资格。步骤创建、开始和结算先锁账户生活状态，使在途判断能发现新步骤或结果；已完成事项不接收迟到进度覆盖，结果未知的步骤只有明确放弃时才转为取消。

业务模块经事务内入口把步骤关联到真实 `jobs`，按任务外键批量结算全部共享步骤、事项进展与事实。同一任务的额外完成事件可一并传入，正常路径只取得一次生活状态锁，并批量写入事实与系统记忆。结果和完成证据的关系见 [生活字段字典](../../../docs/DATABASE_FIELDS.md#生活夜间与调度)。

有意义事件由装配层投影为带显式槽位及 `source_event_id` 外键的系统记忆，批量投影使用嵌套事务；批量失败后按事件分别隔离重试，使单条异常不阻止其余索引。失败保留事实及业务结果并记录诊断，不回滚真实业务。HTTP 只读，跨模块仅经 `use_cases.py`、查询 DTO 和装配端口协作。

事项与事件列表使用时间戳和 ID 的稳定游标，精确总数显式请求时额外查询一次。生活上下文不调用带总数的列表入口。事项按更新时间排序，事件按发生时间排序；同时间戳用 ID 消歧义。
