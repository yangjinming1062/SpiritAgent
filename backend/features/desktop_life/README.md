# 桌面生活

拥有独立桌景套装库、分步制作草稿、当前成品及播放事实。自定义动作语义和评审归共享动作目录，本模块持有每套桌景的独立画面版本。体验归 [DESIGN](../../../docs/DESIGN.md#桌面生活视频)，跨模块契约归 [PROTOCOL](../../../docs/PROTOCOL.md#桌面生活视频与模式隔离)，参考、画幅、媒体及恢复要求归 [PIPELINE](../../../docs/PIPELINE.md#桌面生活视频)。

| 入口 | 职责 |
|---|---|
| [service.py](service.py)、[repository.py](repository.py)、[action_sync.py](action_sync.py) | 套装、共享动作目标事务、草稿检查、自动采用、基准失效与播放事务 |
| [creation.py](creation.py)、[generation.py](generation.py)、[prompts.py](prompts.py)、[video_queue.py](video_queue.py) | 活动计划、画面检查与修复、冻结参考、图片调整、运动设计、视频制作、上传及提交前有效性检查 |
| [queries.py](queries.py)、[use_cases.py](use_cases.py)、[companion_actions.py](companion_actions.py) | 冻结桌景上下文、HTTP 与伙伴当前动作的公开快照 |
| [lifecycle.py](lifecycle.py)、[backup.py](backup.py)、[backup_assets.py](backup_assets.py)、[asset_references.py](asset_references.py) | 任务恢复、备份和资产引用贡献 |
| [naming.py](naming.py) | 按实际画面自动命名及存量默认名称补全 |

所有状态写入共用账户行锁，进程内单飞只协调任务，模型等待在事务外。`source` 决定 `context_json` 的严格结构：AI 使用 `DesktopVisualSnapshot`，上传使用 `DesktopUploadSnapshot`，统一经 `parse_desktop_context` 读取。AI 来源库通过公开快照读取，冻结参考的资产引用独立于来源条目生命周期；上传独立持有原件与参考画面，不记录衣柜、场景、角色资产外键。上传独占来源键由创建时随机生成，不能从文件哈希、路径或数据库 ID 推导；内容相同的新桌景仍是另一目标。内容哈希用于校验，不代表套装身份，当前衣柜和场景指针不约束制作。

默认名称（空名称、「我的桌面背景」及英文默认名）在安静相伴图片或视频真实首帧就绪后后台命名，优先读取当前成品，其次读取已通过检查的草稿。上传桌景在同一次视觉读取中提取并保存实际着装，已有自定义名称也须补全尚未识别的上传着装；原上传参考和各成品分别持有对应画面的描述，采用或分析衍生成品不反写原件描述。AI 着装仍使用冻结的素材描述。着装提取使用必填字符串契约，无可辨认造型为空字符串；字段缺失、空值及超长结果在结构化调用内处理，不作为成功结果写回。启动与账户维护恢复扫描待补资料，读取列表不调用模型。同账户串行，写回前重锁复核原名称、更新时间、画面与素材版本；任务随账户维护取消，退出时回收。视觉分析失败保留原名及真实未识别状态，等待下一次恢复或画面就绪再试；已有其他名称不自动改写，资料提取不改变制作和播放状态。

共享动作按冻结原始身份与着装来源匹配 AI 桌景；上传桌景使用本目标作用域，通过同一目录完成评审、去重和调度，不向其他目标扩散。独立版本首次登记为待制作，不持有供应商进度。新动作的持久制作意图归共享目录，手动占位只能经用户请求开始；AI 套装创建提交后经注入端口补齐关联。来源就绪由本模块统一判定，创建关联、制作入口、恢复和视频提交复核同一条件；安静相伴生效时在同事务登记待调度目标，提交后经注入端口通知共享目录。安静相伴、同步动作及用户重做画面均在完整图片检查通过后自动制作视频，视频检查通过后自动采用。就绪条件与已提交任务处理归[动作契约](../../../docs/PROTOCOL.md#动作目录与播放)。

当前成品与唯一草稿分离，通过检查的图片绑定实际输入图；改图使旧检查和运动脚本失效。具体活动计划、用户定制、系统修复资料与预算随草稿保存，采用后保留计划；成品描述向聊天、自主选择及复用评审提供具体活动和生效要求，制作入口仍读取预设或自定义目标。服务端按状态处理 `retry`，客户端只消费恢复动作。预设默认衔接与草稿、成品的实际衔接分离，共用图条件不足可在草稿中转独立画面。制作冻结资料、预算及并发校验归 PROTOCOL。采用基准同事务作废真正依赖旧基准的草稿、指令与派生资格，并记录后续更新待办；跨任务调度通过 bootstrap 注入回调，不能在事务内触发模型。创建事务先保存输入，前置检查失败仍可恢复。暂停先等待本地任务落盘，再重锁复核草稿；继续不能把上传来源改成新 AI 制作，恢复边界归 PROTOCOL。

活动规划、修复要求、运动设计和视频评审使用结构化视觉调用：格式校验在供应商链内完成，共用一次格式校正预算，校正保留已取得的支持性、失败类型及评审决定。格式错误、分析不可用和画面不合格分别收尾；失败保留实际停止阶段与公开原因，不能把原图回填为合格候选。已有带失败原因的已检查图片草稿按失败投影，重试继续规划与检查。已有合格候选的检查读取失败续审原图；冻结参考副本缺失时，只从任务保存的编辑底图或内容哈希匹配的套装、派生参考恢复，不改用当前外观。

`geometry.py` 读取素材显示尺寸，[video_planning.py](video_planning.py) 与媒体图像链按冻结桌面尺寸选档；裁切、占位检查和真实首帧提取归基础设施媒体层。视频调整由 `video_refinement.py` 预检输入与供应商规格，预检不写草稿，`service.py` 负责冻结来源、要求和调用链。上传接口只导入相应上传套装的安静相伴首次素材，校验并保存原件后在账户锁内锁定，已锁定套装不能重新上传。输入引用与供应商成品分别保存，不能将参考视频写入生成结果的 `source_path`；上传、适配与采用规则统一见 PIPELINE。

数据迁移 `0003` 为上传桌景分配独占来源，保留动作 ID、成品和有效草稿，将原有共享动作关联复制为本目标定义；其他目标的共享定义不变。依据按安静相伴已采用原件、上传草稿原件、确认基准或成品真实首帧选择，不能用缩略封面或素材库猜测缺失来源。无法找到可靠依据的套装保留播放并阻止新增制作。迁移暂停在途推进；供应商视频句柄和未知提交保留，已提交任务独立收尾，继续仍由用户明确发起；已有待确认项由 `0004` 按保存的检查证据收敛。升级无法安全还原错误的来源关系，回退须恢复升级前备份。备份保留固定来源及来源锁，恢复不启动制作。

AI 桌景的完整身体身份来源首次制作新构图时，先用[参考对齐](../appearance/visual_identity.py)合并身份与旧造型，通过身份及画面要求检查后再用作姿态图的造型参考。对齐与姿态各持独立图片链；派生路径、内容哈希和冻结来源保存在制作进度，不改套装快照、来源哈希或衣柜。对齐候选已落盘而检查暂不可用时仅续审，已取得的决定不重判，未知提交禁止重发；合格派生图恢复时复核哈希并复用。用户选定的图片供应商也约束对齐；无可复用结果时会增加图片制作与检查调用。头像来源、已有姿态恢复、编辑、扩图和上传不进入这一步。派生素材随草稿持有，替换、放弃与采用后由既有资产引用清理回收。

制作按任务状态互斥，播放冷却由本模块策略管理。普通制作与视频调整均在输入准备完成后进入公共视频队列，提交与轮询由队列拥有；本模块在实际提交前核对草稿代次、图片检查结果、分辨率和实际基准依赖。排队引用及进度随草稿持久化，暂停未提交尝试后恢复会重新排队，已提交尝试继续收尾。采用和备份恢复语义统一见 PROTOCOL。验证重点包括无文本默认流程、缺少活动用品的自动修复、共用图转独立画面、检查中断与预算恢复、当前成品和不同衔接草稿并存、来源库删除后的继续制作、图片检查、视频参考来源绑定、基准更新、分辨率修订、迟到结果、原始字节、旋转与 SAR、备份和客户端真实播放。
